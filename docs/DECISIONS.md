# 결정 기록

- 스택: Next.js 14 + TypeScript. Python 데모는 규모 미달.
- 호스팅: Vercel + Supabase 무료枠. 계정·배포는 사용자.
- DB: DAL 추상화. 로컬 SQLite, 운영 Postgres. 스키마 단일 관리.
- 인증: dev 별명 우선, Supabase JWT 검증 코드 준비. 토큰 노출은 수용 위험.
- 지도: Leaflet+OSM. 키 불필요. Naver·Kakao는 키 확보 후 교체.
- 저장: localStorage 전량 서버 이전. 브라우저별 격차 해소.
- 집톡이 범위: 정리·안내만. 판단·확정·특약·법률해석 금지.
- 테스트: 47개. 거짓 통과 0건 원칙. 실패는 원인부터.

## 2026-11-01 · P7 핵심 제품 결정 (이전 초안보다 우선)

- **개발 단계:** 정식 서비스 이전 PoC. 법률 적합성 확정은 변호사/관할기관·실사업 모델 확정 시 별도 수행한다. 확인되지 않은 위험을 감추지 않고 `docs/legal/*`에 OPEN으로 남긴다.
- **집톡이 역할:** 거래 조건을 직접 흥정·조율·알선하거나 양측 대신 승낙·금전·계약·방문을 확정하지 않는다. 사용자 발언·DB 승인 상태를 정리하고 미확인 사항/근거/다음 확인 절차를 조용한 보조 카드에 표시한다.
- **거래 사실 기준:** 실제 방문 승인 = `owner_visit_bookings.status=confirmed`; 실제 조건 동의 = `room_proposals.status=agreed` + 동일 버전 양측 사람 동의. 시연방 상태와 혼합하지 않음.
- **등기 권리관계 도구:** 외부 사업자 계약 전에 먼저 최소 정보의 로컬 수동 분석(현행/말소/미확인, 등기구분, 날짜/순위번호, 채권최고액)을 구현. 안전등급·회수가능액·법률우선순위 자동 판정은 하지 않는다.
- **금액 모델:** 채권최고액은 실제 대출잔액이 아니므로 분리해서 표시. 일부 금액이 없으면 합산값 숨김. 법령상 정해진 유효기간이 아닌 앱 자체의 재확인 알림(7일)으로 표시.
- **개인정보/등기 API:** 누구나 개별 등기사항증명서를 열람할 수 있다는 사실과 외부 제휴 API의 재이용/대량수집 허용 및 개인정보 국외전송의 적법성은 별도. 공급 계약과 적법 처리 근거를 확보하지 않은 원본 PDF의 외부 Meta 전송은 계속 차단한다.
- **신원검증:** Supabase 계정 로그인(A)과 인증기관 실명확인(B) 및 특정 부동산의 소유·임대·위임권한(C)은 별도. 운영 인증기관이 연결되기 전 verified를 자동 부여하지 않는다.
- **개발 로그:** 설계 결정·근거 법령·코드·테스트·PR·미검증 범위를 `docs/DEVELOPMENT_LOG.md` + 해당 단계 설계문서에 남기고 이전 기록은 삭제하지 않는다.
- **외부 의존 보류:** 실사용자 2명 거래 E2E, 실명확인기관 계약, 실 등기 API 업체 계약, 법률 자문·개인정보 실사. 개발 자체는 계속하되 미완료를 완료로 표시하지 않는다.
