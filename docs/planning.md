# P2P 부동산 직거래 기획 v1

## 1. 문제 정의

- 중개수수료 부담이 크다.
- 직거래는 하고 싶지만 법적 리스크가 무섭다.
- 등기부는 어렵고, 계약서 특약은 더 어렵다.
- 사기 유형: 무권리자 계약, 이중 계약, 보증금 미반환, 허위 매물.

## 2. 타겟 사용자

- 임대인/매도인: 수수료 없이 빠르고 투명하게 올리고 싶다.
- 임차인/매수인: 싸게 구하고 싶지만 사기당하고 싶지 않다.
- 1차 타겟: 월세/전세 소형 거래, 이후 매매로 확장.

## 3. 핵심 가치

- 매물을 올리면 위험이 보인다.
- 합의하면 계약서 초안과 특약이 나온다.
- 법률 자문이 아니라, 이해 가능한 요약과 체크리스트로 거래를 돕는다.

## 4. 핵심 기능 1: 등기부 및 위험도 자동 분석

### 입력

- 사용자가 올린 등기부 PDF/이미지.
- MVP는 업로드 기반, 이후 열람 연계 검토.

### 파이프라인

1. 파서가 주요 필드 추출: 소유자, 근저당, 압류/가압류, 전세권, 지상권, 을구 권리 순위.
2. Meta Model API(Muse Spark)가 매수인용 요약 생성.
3. 결과는 등급+근거+다음 행동으로 보여준다.

### 출력 예시 구조

- 위험 등급: 안전/주의/위험.
- 한 줄 요약: 초등학생도 이해되는 문장.
- 근거 목록: 금액, 권리자, 순위, 말소 조건.
- 권장 다음 단계: 특약에 넣을 문장, 확인 서류.

### 설계 원칙

- 원문과 추출값을 함께 보여준다.
- 법률 확정이 아니라 참고용임을 명시한다.
- 개인정보는 마스킹 후 LLM에 전달한다.

## 5. 핵심 기능 2: 계약서 및 특약 생성기

### 입력

- 매물 상태: 위 기능의 위험 분석 결과.
- 합의 내용: 보증금, 월세, 입주일, 관리비, 수리 책임, 중도 해지 조건.

### 흐름

1. 거래 체크리스트 안내: 신분 확인, 소유자 확인, 대리인 위임장, 관리비 체납, 확정일자, 전입신고.
2. 합의 내용 입력.
3. Muse Spark가 매물 상태 맞춤형 특약 초안 작성.

### 특약 예시 방향

- 근저당 있음: 잔금 전 말소 조건, 말소 불이행 시 계약 해제/반환.
- 전입/확정일자: 대항력 확보 기한 명시.
- 하자/수리: 입주 전후 수리 책임과 비용 분담.
- 중개 없는 직거래 고지: 쌍방 직거래 확인 문구.

### 설계 원칙

- 템플릿+LLM 하이브리드: 고정 필수 조항은 템플릿, 상황 문장은 생성.
- 모든 생성문은 체크박스 검토 후 확정.
- 최종본은 PDF 저장과 버전 기록.

## 6. 그 외 MVP 범위

- 매물 등록/검색/상세.
- 합의 상태 관리: 협의중/합의완료/계약서 작성중/서명대기.
- 거래방: 조건 합의 로그 남기기.
- 관리자: 허위 매물 신고 처리.

## 7. 비MVP

- 전자서명/결제 연동.
- 실거래가 자동 검증.
- 보증보험 연계.
- 모바일 앱.

## 8. 기술 방향(가안)

- 웹 우선, 스택은 미정.
- 서버: 매물 API, 파일 업로드, Muse Spark 호출 프록시.
- DB: 매물, 위험 분석 결과, 합의, 계약서 초안 버전.
- 외부 호출은 서버에서만, API 키 노출 금지.

## 9. 리스크와 대응

- LLM 환각: 원문 근거 없는 문장 금지, 템플릿 가드레일.
- 법률 책임: 변호사 검토 문구와 면책 고지.
- 개인정보: 등기부 마스킹, 원본 접근 권한 분리.
- 사기: 소유자 인증과 계좌명 확인 절차를 체크리스트에 포함.

## 10. 다음 단계

1. 등기부 샘플 3건으로 추출 필드 확정.
2. Muse Spark 요약/특약 프롬프트 초안 작성.
3. 매물 상세 화면에 위험 요약 UI 스케치.
4. 합의 입력 폼 필드 확정.
5. 스택 확정 후 MVP 스캐폴딩.
