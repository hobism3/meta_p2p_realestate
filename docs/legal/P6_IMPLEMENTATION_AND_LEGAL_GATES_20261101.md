## P0 미해결 위험
- 서비스가 실제 중개업인지 **미확정**. 사업자·유료/광고/성사보수·플랫폼 개입 수준에 관한 법무 자문 필요.
- 등기 원문 유료 API의 **법원/벤더 이용 허용, 개인정보 적법한 근거, 원본 출처/계약** 미검증. 광고주 및 중개인 관계 검증 별도.
- 신원확인 제공자 계약·운영 비밀키 미제공으로 실제 본인인증 완료 상태를 만들 수 없음. 현재는 provider-neutral 브리지 코드만 준비.
- 소유권·위임관계 인감/신탁/법인/공유자 증빙과 외부 법원 데이터 연계 미구현. 게시 계정 자기진술은 인증이 아님.
- 실제 공개 매물에 대한 필수 광고 표시정보 및 확인/신고/삭제/모니터링 전반이 2026-12/2027-06 예정 규정에 맞춰 고도화되어야 함.
- 개인정보처리방침/수탁사 계약/국외이전 고지/고객 데이터 접근·삭제/보존정책·실운영 법무 승인 필요.
- 실계정 2인 전체 거래 QA는 사용자 요청대로 보류. Mock/CI PASS는 실제 거래 법률 준수나 프로덕션 테스트 대체 불가.

## Test/release gate
1. verify-fast build·unit·API 필수. verify-e2e 결과는 참고하되 명백한 기능 오류는 해결.
2. PR 변경 커밋에 CI PASS 확인한 뒤 main 병합. 배포 최신 SHA 확인 전 Production 완료 주장 금지.
3. 마이그레이션은 기존 DB 데이터 손상 없이 적용되고 다른 계정이 신원·매물 관계나 신고 관리 내용에 접근할 수 없음을 격리 API 테스트.
4. 외부 본인확인기관·등기 API 자격증명이 없는 상태에서 '인증 완료' 표시·소유권 추정/법률 적합성 인가 금지.
5. 법률 시행 전/후 규제 상태를 주기적으로 재검토하고 보고서 기준일을 남길 것.
