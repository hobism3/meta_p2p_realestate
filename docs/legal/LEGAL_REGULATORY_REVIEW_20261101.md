## 2. 이슈별 법률 분석 및 코드 대조

### LEG-01 [P0] 공인중개사법상 중개행위 경계
- 근거: 공인중개사법 제2조·제9조, 위 대법원 판례.
- 관찰: `web/lib/owner-delegate-service.ts`는 등록된 소유자 매물의 사실 기반 응답, 승인 필요 질의의 소유자 handoff를 처리. `web/app/rooms/[rid]/page.tsx`는 제안 및 양측 확인 UI를 운영. README에서는 플랫폼을 직거래 지원 서비스로 설명.
- 위험: AI가 양 당사자 사이에서 절충·가격 교섭·성사 유도를 수행하거나, 성사 성과에 연동한 보수를 받으면 중개업 등록 필요성 쟁점이 커짐. **무료라는 사정 하나만으로 모든 중개행위 문제가 해소된다고 단정 불가**.
- 현 정책: AI 자율 흥정/조건 결정/계약 체결/정산/성사보수 기능 금지. 집톡이는 양측 발언을 요약하고 명시 동의만 기록.
- 출시 게이트: 법무사/변호사에 기능별 actor-action-payment 매트릭스 검토; 사업자 역할과 유료화 구조 확정. 관할 등록관청·국토교통부 유권해석 필요 여부 판단.

### LEG-02 [P0] 등기부 PDF 및 Meta 전송과 개인정보
- 근거: 개인정보 보호법 제15조·제21조·제29조·제30조 및 국외이전 관련 규정.
- 관찰: `web/components/RegistryImport.tsx`는 PDF를 base64 형태로 서버에 전달하며 `consent` 체크. `docs/REGISTRY_AI_IMPORT.md`는 서버의 마스킹 및 외부 Meta Model API 전송, 원본 비영구 저장을 설명.
- 위험: 단일 체크박스만으로 수집·외부 제공/위탁·국외이전 요건 충족을 증명할 수 없음. 등기부의 소유자 등 **업로더 이외 제3자의 정보**가 포함될 수 있어 업로더 동의만으로 처리가 정당화되지 않을 수 있음. '마스킹' 구현의 실제 비식별 성능과 Meta 데이터 처리·보관 조건 미검증.
- 즉시 운영 권고: **실제 등기부 업로드/Meta 전송 기능은 법률·개인정보 검증 완료 전 비활성화**. 샘플 Mock 흐름만 공개. 동의 문구와 데이터 흐름/국외이전/수탁자·보관기간/삭제 정책의 분리 문서 필요.
- 출시 게이트: 개인정보 처리방침·수집 근거 표·처리 위탁/국외이전 정합성·삭제 재현·접근 로그·하위 처리업체 검토, 원본 PDF와 모델 프롬프트에 대한 비밀/PII 로깅 테스트.

### LEG-03 [P0] '양측 확인'과 계약 법적 효력 혼동
- 근거: 전자문서법 제4조/제4조의2, 전자서명법 제3조.
- 관찰: 거래방은 확인 카드 및 상태를 저장하며 README는 시연 동의가 법적 서명/예약이 아님을 표기.
- 위험: 전자적 동의의 효력이 일률적으로 없는 것도, 자동으로 적법한 부동산 계약이 성립하는 것도 아님. 당사자 의사/계약 성립·서명자 동일성/필요 서류 등 개별 검토 필요.
- 정책: 용어는 '거래 조건 확인(플랫폼 내 기록)'으로 제한. '계약 완료', '법적 확정', '안전 거래 보장', '자동 계약 체결' 표현 금지. 본인확인/서명·기록무결성 기능 전에는 전자계약 기능 출시 금지.

### LEG-04 [P1] 직거래 매물 광고·게시자 신뢰
- 근거: 공인중개사법 제18조의2와 시행령, 표시광고법 등 적용 가능성.
- 관찰: 소유자가 직접 매물을 등록할 수 있고 등기 PDF → 등록 초안 추출은 실제 소유권 확인이 아님.
- 위험: 공인중개사법 표시광고 규제의 적용 주체·요건은 게시자와 운영 형태별 별도 판단 필요. 플랫폼 자체가 중개업을 영위하는 형태가 되면 위반 위험 확대. 허위 매물/가장 소유자/권리관계 오류.
- 조치: '집주인 인증 완료' 표지 금지(확인 과정 미구현). 신고·수정/삭제·게시 이력·재검증 정책 마련. 사업모델과 광고 책임 관계를 법무 검토.

### LEG-05 [P1] 부동산 매매·임대차 신고/권리 보호 안내
- 근거: 부동산 거래신고법 제3조, 주택임대차보호법 등.
- 정책: 매매/임대차의 신고, 전입·확정일자, 보증금·선순위 권리 확인은 사용자의 후속 절차 안내 수준으로만 제공. 거래유형·지역/금액에 따른 신고대상과 기한은 조건부로 안내하고 공식 출처로 연결. 자동 신고 완료 주장 금지.
- 출시 게이트: 매매/전월세별 체크리스트 별도 법률 검수.

### LEG-06 [P1] 생성형 AI 안내 책임
- 관찰: 집톡이는 근거 연결과 양측 확인 원칙을 따르나 사용자에게 '안전/위험' 법적 결론을 줄 경우 오인 우려.
- 정책: '법률 검토 완료', '사기 아님', '안전 거래' 등의 보증표현 금지. 근거 데이터·검증되지 않은 추론·사용자 확인 항목을 구분. 위험 점수는 교육/참고 정보로만, 오탐·누락에 대한 사용 설명 필요.

## 3. P0/P1 운영 보류 기준
- P0: 중개업 해당성에 대한 법률의견 + 서비스 수익모델 확인 없이는 **실거래 유료 출시 보류**.
- P0: 실문서 업로드/국외전송과 동의/처리방침 검증 없이는 **실문서 기능 보류**.
- P0: 본인확인·법적 계약 설계 없이는 **전자계약/계약 체결 완료 기능 보류**.
- P1: 허위 매물 신고/삭제/차단 운영 정책, 게시자 검증, 거래 후 신고 안내의 근거 검수.
- Demo: 합성 매물·허구 등기 PDF·Mock 계정만 사용. 모델 출력은 법률 판단 아님을 공지.

## 4. 개발 지시(권장, 별도 PR)
1. `REGISTRY_AI_ENABLED=false`를 실운영 기본값으로 유지하고 Meta 실문서 호출에 서버 측 operator-only feature flag 및 다중 확인을 추가.
2. 실거래 UI 전역의 '동의/확정/계약' 문구를 감사해 계약 법적 효력과 구분되는 텍스트로 수정. 기능 동작은 변경하지 않음.
3. 처리방침·서비스 이용약관(초안)과 공개 전 법무 확인 체크리스트. 추정·미확정 사실을 선언형으로 공표하지 않음.
