> 기준: 2026-11-01 KST · 검토 대상: `main@94108e1` + 법률보완 브랜치 · 법률 실사(쟁점 검토), **변호사 자문·적법성 보증 아님**
> 사용자가 실사용자 2명 종단간 거래 QA를 보류함. 따라서 실서비스 적법성, 외부 API 계약, 운영 배포, 개인정보 처리방침 실제 게시 여부는 **확인되지 않았음**.

## 0. 집행 요약과 종전 보고서 정정
1. **신규 법률 누락 정정:** 「부동산 거래신고 등에 관한 법률」 법률 제21815호(2026-06-16 공포)의 제23조의2·제23조의3은 **2026-12-17**, 제23조의4·제23조의5는 **2027-06-17**부터 시행 예정. 직거래 플랫폼 사업자 본인/소유자 관계 확인·확인 여부 표시, 유의사항 안내, 자료 제출/광고 모니터링 대응과 직접 연관.
2. **중대한 코드 오류 정정:** 종전 `REGISTRY_AI_IMPORT.md` 및 1차 법률 검토가 '마스킹된 PDF를 Meta에 전송'한다고 설명한 점은 부정확. `web/lib/registry-draft.ts:buildRegistryMetaRequest`는 외부 Meta 요청에 **원본 PDF 전체를 base64**로 포함시켰고 `validateRegistryDraft`의 PII 필터는 **응답 후처리**. 파일 이름 `redacted-registry.pdf`는 문서 내용 자체의 마스킹 증거가 아님.
3. **즉시 완화:** 법률보완 브랜치에서 hash 일치 **합성 시연 PDF 두 개**만 Meta 전송 가능하도록 서버 측 차단(`isSyntheticRegistryDemoPdf`) 및 회귀 테스트 추가. 아직 운영 반영/배포 확인 전이므로 **운영 위험 제거 완료라고 단정 금지**.
4. **거래 합의에 대한 과도한 안심 금지:** 전자서명 버튼이 없더라도 채팅의 의사표시와 클릭은 사정에 따라 실제 계약 의사로 평가될 수 있다. '플랫폼 내 확인'이라고 표시하는 것은 중요한 UX 안전장치지만 민법상 계약 성립을 일률적으로 차단하지 못한다.
5. **실제 상품/광고 이중성:** 기본 합성 시연 매물과 사용자 임의 등록 매물이 동일 검색 API와 지도에 함께 노출된다. '전체가 합성' 표기는 부정확하며 실제 권리자가 아닌 사용자도 가입만으로 매물 등록 가능. 사용자 게시물의 공개상태/검증 의무는 별도 설계 필요.

### 법적 결론 상태
- **출시 보류(P0):** 실제 개인정보 포함 등기부 외부 전송, '소유자 인증' 표기, 법적 계약 보장/전자계약 처리, AI의 플랫폼 주도 가격 절충 및 보수 연동 중개.
- **구현은 했으나 미검증:** mock/메시지/소유자 승인 정책 등 기능 경계, synthetic-only 서버 수정, 검증 전 사용자 게시물 경고.

## 2. LEG-01 · 중개행위 해당성 (P0)
### 법률 구조
공인중개사법 제2조는 '중개'를 중개대상물의 매매·임대차 등 권리변동을 **알선**하는 행위, '중개업'을 **다른 사람의 의뢰에 따라 일정 보수를 받고 중개를 업으로 하는 것**으로 규정. 제9조는 중개업에 등록을 요구. 무등록 중개업은 제48조 벌칙 위험.

대법원 **2024.12.26. 2024다280898·280904**: '컨설팅'이라는 형식이 실제 객관적으로 중개인 행위를 자동으로 제외하지 않음. 부동산을 양도하는 거래의 알선 실질을 판단. 원문 https://www.law.go.kr/LSW/precInfoP.do?precSeq=609447
대법원 **2021.7.29. 2017다243723**: 중개업자가 한쪽 당사자의 의뢰에 따라 알선하는 경우도 '중개'에 포함. 원문 https://www.law.go.kr/LSW/precInfoP.do?precSeq=217379

## 3. LEG-07 · 2026~2027 신설 '직거래 플랫폼법' 대응 (P0)
### 정확한 시행 구분
- **2026-12-17:** 제23조의2는 거짓 개발정보/왜곡 시세 등 거래 유인 허위정보 유포 금지. 제23조의3은 인터넷 부동산 광고의 소재지·면적·가격 등 필수 정보와 허위/과장 광고 금지.
- **2027-06-17:** 제23조의4는 직거래 플랫폼 운영사업자가 **게시자 본인 여부 및 부동산 소유자와의 관계 등** 대통령령 사항을 확인하고 **확인 여부를 이용자가 볼 수 있도록 표시**하도록 규정. 제23조의5는 국토교통부 모니터링, 자료 제출 및 시정요구 대응 근거.
- 근거: 법률 제21815호 부칙(6개월/1년), 제정·개정문 https://law.go.kr/lsInfoP.do?lsiSeq=286987&viewCls=lsRvsDocInfoR

### 현재 코드와 간극
- `web/app/api/listings/route.ts`: 이메일/Google 인증 후 주소·게시자명·면적·가격 입력만으로 게시. **게시자가 소유자인지 또는 적법한 대리인인지 서버 확인 없음**. `publisher`는 사용자가 직접 입력할 수 있음.
- `web/app/api/listings/[id]/route.ts`: 실운영 Supabase에서 수정 권한은 게시 계정 owner_id와 비교하지만 **해당 부동산의 소유권 증명은 아님**. 개발 모드에서는 별명 기반 권한으로 약함.
- `web/app/listings/[id]/page.tsx`: 이전에는 '본인 인증 제출됨/서류 제출됨' 배지가 실제 확인처럼 보일 수 있었고 '정보 오류 신고(시연)' 클릭은 서버 신고 접수가 없었음. 브랜치에서 미검증 상태 명시 및 가짜 접수 UI 제거.
- `web/app/api/listings/route.ts:GET`: 사용자 등록 매물과 합성 매물 혼합 공개. 분류/신원 여부 노출 필요.

### 필요한 최소 운영 설계
1. **신원 확인(subject)**, **매물 관계 확인(ownership/agency)**, **게시권한 검증(status)**을 서로 다른 상태로 저장. `unverified/pending/verified/rejected/expired`.
2. 소유자 외에 임대인·공유자·정당한 위임인 등 관계의 판단은 '본인=등기 소유자'와 다르다. 확인 방법과 허용 관계 범위를 변호사·시행령 검토로 확정. 주민등록번호 수집은 법적 근거 없이 금지.
3. 문서 검증 완료·유효기간·검증 방법·검증자/자동 판정 범위·갱신 필요 상태를 분리. **업로드=검증완료 아님**.
4. 게시 화면에 확인 여부를 이용자에게 표시, 신고/삭제/이의제기·오래된 매물 정리, 게시 이력과 운영자가 받아야 할 자료 제출 대응 장치 마련.
5. 시행령 위임 사항에 따라 광고 표시 필드를 보충. 현재 면적/가격/주소만으로 시행령 의무 충족을 단정하면 안 됨.
6. 법률상 플랫폼 의무 시행 전이라도 실제 매물 게시를 허용할 경우 허위 광고 및 개인정보·민사 책임을 별도 관리.

## 4. LEG-02 · 개인정보 및 등기부 국외전송 (P0)
### 실제 데이터 흐름
`RegistryImport.tsx`: 브라우저 PDF 바이트 → base64 JSON → 서버 `POST /api/listings/import-registry`.
`route.ts`: 사용자 인증/용량/동의 확인 → PDF 원본 메모리 로딩 → (기존) `buildRegistryMetaRequest(pdf)` → Meta URL `https://api.meta.ai/v1/chat/completions` → `validateRegistryDraft()` 출력 필터 → 응답.
**출력 필터를 '업로드 문서 마스킹'이라 부르는 것은 오류**. 외부 요청에는 원본 PDF(갑구·을구·소유자·제3자 권리자 등)가 포함될 수 있었음.

### 관련 법률과 판단
- 개인정보 보호법 제15조는 수집·이용의 적법 처리 근거 필요; 제24조의2는 주민등록번호 처리에 **매우 엄격한 법정 요건**(단순 동의만으로 자유롭게 처리 불가).
- 제26조는 처리위탁의 문서화·수탁자 공개·감독. Meta가 법률상 제3자 제공인지 위탁인지(또는 복합) 계약상 역할·처리목적에 따라 구분 필요.
- 제28조의8은 국외 제공·위탁·보관의 허용 근거를 요구. 특히 **정보주체와 계약이행에 필요한 위탁/보관 + 고지/공개** 예외는 모든 제3자 정보의 외부 이전에 자동 적용되지 않음. 국외이전 별도 동의를 선택하면 이전 항목/국가/방법·시기/수령자/목적·보유기간/거부 효과 등 고지 필요.
- 등기부가 열람 가능한 공적 기록이라도 개인 관련 정보의 모든 재사용·AI 국외전송이 자유로운 것은 아님. 업로더 1명의 동의로 PDF에 기재된 제3자 전체의 권리를 대리할 수 없음.
- '서버 저장 안 함'은 일시 처리·네트워크 전송·제공자 보관·로그/재시도/백업 전반의 적법성 입증에 충분하지 않음.

### 즉시 코드 통제 (이 PR)
- 샘플 생성 PDF와 별도 고정된 허구 등기 샘플의 **정확한 SHA-256**만 Meta/Mock 경로 허용. 임의 PDF는 Meta 호출 전에 422 거절. 서버가 결정하며 체크박스, PDF 이름, 업로드 사용자 주장만 신뢰하지 않음.
- 출력 필터는 계속 유지하지만 **입력 비식별화로 오인하지 않도록** API 문구/파일명/UI 수정.
- 합성 샘플은 Meta에서도 1회 전송될 수 있어 UI에서 명시.
- 이 제한은 **Meta 송신**을 차단할 뿐, 사용자가 부주의하게 실문서를 플랫폼 서버에 보낼 수 있는 위험을 원천 제거한 것은 아님. 다음 개선: 브라우저에서 파일 해시를 먼저 확인해 합성 외 파일은 업로드 전 거부.

### 실문서 지원을 재개하려면 (별도 P0 법률·기술)

## 5. LEG-03 · 거래 조건 카드와 계약 성립 가능성 (P0)

- 전자문서법 제4조는 전자적 형태 자체만으로 법적 효력이 부인되지 않음을 명시하고, 전자서명법은 법적 효력 체계를 규정.

- **핵심 오인:** '전자서명을 제공하지 않으니 채팅은 결코 계약이 아니다'라고 보장 불가. 반대 극단으로 카드 양측 동의 시 자동으로 법적 부동산 계약 성립/전자계약 완성이라고 주장해도 안 됨.
- **권고 UX:** 플랫폼 내 조건 확인 이력임을 분명히 하되, 실제 채팅·버튼 동의가 법적 의사표시로 평가될 가능성을 명시. 별도 본인확인·계약서 완성·전자서명·등기/신고·결제 기능을 제공한다고 오인시키지 않음.
- 법률 보완 브랜치에서는 `TransactionProgressPanel.tsx`에 이 경계를 표시하는 안내문 추가.
