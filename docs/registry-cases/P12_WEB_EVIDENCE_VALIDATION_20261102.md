# P12 · 외부 공개자료 기반 검증 전환 (Human Label-Free Evidence Triangulation)

2026-11-02 · 대상 `main` P11 `26ed25a` 이후 · 브랜치 `feat/p12-web-evidence-triangulation-20261102`.

## 0. 사용자 요구와 결정
사용자는 등기부 판단 전문가가 아니며 별도 사람 정답 라벨을 작성할 수 없다. **전문가가 문서 전체의 정답을 하나씩 주석해야만 개발을 진행할 수 있다는 기존 P11 후속 가정을 철회**한다.

대체 방법은 다음을 서로 구분해 동시에 진행한다.

1. 공개 원문 PDF를 실제로 내려받고 SHA-256으로 식별한다. PDF 링크만 찾았거나 논문에 그림이 실렸다는 것과 실제 원본 확보는 구분한다.
2. 공개 PDF 발행자가 **직접 명시한 교육용 예시의 권리/금액**을 부분적인 외부 기준으로 삼는다. 그 설명이 다루지 않는 다른 행까지 모두 정답으로 간주하지 않는다.
3. 국가법령정보센터 법령·공기업/HUG 및 독립 교육 자료를 통해 **권리 유형, 구역, 별도 확인 필요 항목**이 일관적인지 검사한다. 법령상 우선순위/효력까지 자동 판정하지 않는다.
4. PDF 문자 목록 역순/페이지 좌표 평행 이동처럼 동일 원본의 표현만 변환해 파서 **불변성(metamorphic)** 을 검사한다. 불변성 통과는 '정답'이 아니라 재현성이다.
5. 기존 P9와 별개로 **번호 + 등기목적 셀**만 스캔하는 보수적 독립 탐지기를 두고 누락·추출 과잉·부기번호/구역 이상을 경고한다. 두 파서가 일치하더라도 둘 다 놓친 항목이 있을 수 있다.

이 다섯 가지를 섞어 `완전 정확`이라고 부르지 않는다. 앞으로 사용할 표현은 **publisher-backed partial facts / source agreement / observed-row coverage / metamorphic stability / unavailable** 로 고정한다.

## 2. HUG 발행자 원본 설명을 활용한 부분 정답

HUG 웹페이지는 소유주·권리자와 주소를 가린 표를 공개한다. 해당 표에서 **종류·날짜·순위·채권최고액만 추려** `web/tests/fixtures/registry-hug-publisher-cases.v1.json`으로 최소 재구성했다. 표의 원문 전체·인명·주소·주민등록번호를 기록하지 않았다. 이 예시의 필드 정답은 사용자가 입력한 것이 아니라 **기관이 게재한 표 자체에 있는 값**이다.

- `P12-HUG-01`: 갑구 3 압류 + 을구 1 근저당, 금액 200000만원, 날짜 비교. 출력 `status=unknown`, 자동 동의/소유권 확인 아님.
- `P12-HUG-02`: 표제부의 `토지 별도등기 있음(근저당)`을 **해당 건물의 을구 근저당으로 잘못 승격하지 않음**. 후보 0은 보증금 안전 판정이 아니다. 토지 등기부/대지권은 추가 확인해야 한다.
- `P12-HUG-03`: 근저당 채권최고액 20억 원을 정확한 만원 단위로 구조화하되, **실제 대출 잔액·연체·압류상태를 임의 계산하지 않음**.

이들은 **외부 출판 예시에서 유래한 필드 검증**이다. 등기소 실제 발급본의 전체 OCR 정답 정확도를 의미하지 않는다.

## 3. 독립 번호·목적셀 탐지

`web/lib/registry-independent-row-audit.ts`:
- HUG/당당에 공통으로 보이는 **구역 제목+번호/순위+구분자+등기목적** 신호를 원본에서 별도 스캔한다.
- P9의 `extractRegistryText`와 실질적 동일한 구현을 복제하지 않고, 단순 목적셀 prefix를 검사해 `visible numbered risk rows`의 누락 여부를 찾는다.
- `missingInPrimary>0`: 번호/권리 신호가 존재하지만 기존 parser가 후보를 반환하지 않음 → **추가 확인 필요**.
- `notIndependentlyConfirmed>0`: P9가 후보를 만들었지만 독립 번호행으로 확인되지 않음 → **추가 확인 필요**.
- `3-1` 부기번호와 구역 이상 매칭은 자동 rank·priority 판정이 아닌 경고.
- **둘 다 0이면** `insufficient_observable_rows`, 결코 `safe`가 아니다. 이 탐지기는 이미지 문자, OCR 누락, 비정형 표를 모두 잡지 못할 수 있다.
- 외부 공개자료에서 다시 수집한 개인 이름·주소·숫자 원문은 출력하지 않고 카운트와 **고정 사유 코드**만 출력.

## 4. 자동화된 웹 검증과 출처 한계

`web/scripts/check-registry-public-guidance.mjs`:
- HUG/당당 출처 URL을 직접 HTTPS HTML fetch, 문서 3 MiB 상한, 공개 호스트 화이트리스트, 소스의 정확한 인명·본문을 로그하지 않고 **기대 설명이 실제로 존재하는지**만 확인.
- HF 공공기관의 근저당/가압류 체크리스트는 추가 참고 검증(네트워크 접근이 불안정해도 독립 PDF 권리검증 게이트와 혼동하지 않음).
- HUG·당당의 필수 설명을 찾지 못하면 별도 CI Gate가 FAIL. **웹 접속 실패는 무효/정보부족**, 아니면 "권리 없는 안전한 집"이라고 판정하지 않는다.
- 당당 PDF 5종 자체는 P11에서 계속 SHA+종류/최소건수+가상 합계 2억9천만원을 검증하고, 실 원본의 글자 배열·좌표 변형 불변성까지 추가한다.
- **동일 기관이 작성한 가상 PDF와 같은 기관의 해설을 대조하는 것은 독립 정답 2표가 아니다.** 다른 HUG/HF 자료는 권리 유형/경고의 외부 정합성을 높여주지만 당당 PDF의 모든 행에 대한 전문가 승인으로 대체되지 않는다.

## 5. 실사용 판단에서는 안전한 실패 우선

현재 사업은 PoC. 실제 사용자의 계약 상대 신원·권한, 등기 말소선/주석, 임차권·선순위 임차인·체납세금은 원본 문서 한 장의 정형화로 판정할 수 없다. **자동 "안전" 표시·자동 계약 승인/교섭은 계속 금지**.

브라우저 `/registry/extract`의 사용자 확인 절차와 P8 구조화 후보는 그대로 유지하되, 사용자에게 전문가 정답 라벨을 *만들라고 요구하지 않는다*. 실거래 UI에서의 문서 대조는 후보 오류를 줄이는 선택적 확인 단계이며, 개발 단계 검증용 골든 데이터를 제공하라는 뜻이 아니다.

## 6. 다음 데이터 수집 / 비개발자 대조

- 교육용 **공개 원본 PDF**는 원 제공자 URL·SHA로 추적; 제3자 권리 원본의 무단 수집·외부 AI 전송·재배포는 배제.
- P12에서는 기존 7개 PDF 외에 이전에 인덱싱한 **한성대 KOCW·공시법 강의노트 PDF 추가 조회**를 시도한다. 자료 확보 실패·20페이지 상한 등의 사실을 그대로 남긴다. 두 자료에 특정 계약의 실명/주소가 있더라도 테스트 원문에 저장하지 않는다.
- 더 확보될 경우 샘플을 **유형별**(현행·말소/부기/신탁/경매/전세권/동일 권리 변경)로 나누되, 공표되지 않은 기대값이나 정확도 수치를 만들어내지 않는다.
- 문제가 생기면 출처 링크+고정 SHA+분석 시도와 고정 오류코드를 Git 로그에 기록한다. 실제 페이지 스크린샷/원문 PDF 자체는 저작권·개인정보 검토 없이 재배포하지 않는다.

## 7. CI 기준

```sh
cd web
npm ci
npm run build
node --test tests/registry-rights-analysis.test.mjs
node --experimental-strip-types scripts/probe-public-registry-pdfs.mjs
node scripts/check-registry-public-guidance.mjs
```

- GitHub CI `verify-fast`는 HUG 발행자 최소 예시·누락 탐지·출처 메타데이터 테스트.
- `public-registry-educational-corpus`는 공개 PDF 실물 해시/필수권리 타입·금액 + **불변성 및 공개 HTML 확인**.
- `verify-e2e`는 기존 권리화면·세션·권한 회귀.
- 위 검증 성공으로 실 주택의 "법률 위험 분석 정확도 XX%" 같은 측정값을 만들지 않는다.
