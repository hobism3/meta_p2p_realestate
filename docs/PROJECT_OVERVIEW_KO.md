# DirectHome — 프로젝트 소개 (한국어)

**한 줄 정의:** 부동산 직거래에서 발생하는 자연어 협상을 **근거가 있는 거래 조건 → 양측의 명시적 동의 → 거래 현황**으로 연결하는 AI 지원 서비스.

## 문제

직거래에서는 중개비 부담을 줄일 수 있지만 가격, 보증금, 월세, 방문일, 계약·잔금일, 인도·입주일 등을 당사자가 직접 협의해야 합니다. 채팅에 흩어진 제안과 번복, 단순 희망과 실제 합의가 뒤섞이는 것이 사용자 경험상의 문제입니다.

## 핵심 사용자 흐름

**매물 탐색**(지도/리스트) → **독립 거래방** → **AI 매도자/임대인과 대화** → **집톡이가 조건 추출** → **양측에 확인 요청** → **거래 현황에 조건과 근거·변경 이력 저장**.

## AI 역할 분리

- **AI 매도자·임대인:** 합성 매물의 가상 거래 상대방. 매물별 페르소나에 따라 짧고 자연스럽게 답합니다.
- **집톡이:** 제3자 관점의 중립 에이전트. 대화를 읽고 금액·일정·옵션 등 조건을 추출해 근거를 연결하고, 합의가 필요한 시점에 확인 카드를 만듭니다.
- **실제 사용자:** 같은 버전의 조건에 직접 동의하거나 거절합니다. AI 시연용 동의는 실제 집주인의 동의가 아닙니다.

## 거래유형별 핵심 차이

| 유형 | 최종 동의 카드 |
|---|---|
| 매매 | 최종 매매가 1건 |
| 전세 | 최종 전세보증금 1건 |
| 월세 | **보증금+월세 묶음 1건** |

예시: 조용한 주택가 투룸은 **보증금 2,000만 원 / 월세 85만 원**으로 시작합니다. 임차인이 **5,000만 원 / 65만 원**을 제안하고 AI 임대인이 수락했다면 집톡이는 **한 장의 합의 카드**를 제시해야 합니다. 별도의 매수가격 카드 두 장이 생성되거나 AI의 수락을 현실 계약으로 취급해서는 안 됩니다.

## 기술적 차별점

두 AI의 역할과 실행 기록 분리, Meta Muse Spark 서버 측 호출, 원문 메시지 근거 검증, 월세 금액 묶음의 정규화, 제안 버전 관리, 작성자·역할별 동의, 대화방 권한 격리, Mock 기반 CI와 실제 Meta 응답의 명확한 구분.

## 해커톤 시연에서 보여줄 것

*매물에서 대화 시작 → AI 임대인과 보증금·월세 협상 → 집톡이가 묶음 조건 확인 → 사용자 동의 → 거래 현황에 양측 상태 기록*.

현재 단계는 **합성 데이터 기반 해커톤 MVP**입니다. 실물 소유권 검증, 전자계약, 계약금 결제, 실제 방문 예약, 법률 자문은 제공하지 않습니다. 기준 커밋 Fast 308건 + E2E 28건의 Mock/테스트 DB 통과는 확인됐으나, 실제 Meta 전반의 정확도를 의미하지 않습니다.
