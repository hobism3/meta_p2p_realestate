# DirectHome — End-to-End UX Audit (2026-11-02)
**Audit methodology:** GitHub source review of Next.js routes/components, current GitHub CI desktop/mobile Playwright regression, and read-only Vercel health/runtime checks. A hands-on human visual inspection of every Production route has NOT yet been completed. Automated Mock E2E success is not proof of real AI output reliability.

## User journeys examined
| Journey | User objective | Supported path | UX finding / remaining friction |
|---|---|---|---|
| Home seeker | Compare properties and choose a listing | `/` map/list -> `/listings/[id]` -> `/rooms/[rid]` | Seed/demo vs user listing labels matter; preserve clear distinction. Filter controls exist. |
| Owner first visit | Register home without repeating work | `/register` wizard -> photo studio -> success | PR #43 fixes a severe prior reupload/restart problem. Browser tab still retains unsaved photo bytes only in memory. |
| Owner photo AI | Understand spaces/options, preview furniture-free view | Per-photo consent -> AI review -> manual amenity selection -> separate edit consent | PR #43 moves explicit consents above photo cards and clarifies pending/complete states. Model usage caps and uncertainty still need contextual guidance. |
| Owner publication | Share ONLY reviewed actual photos | Save listing -> same photo workspace -> publication consent -> compressed JPEG gallery | Previously published photo looked removable only from local UI; PR #45 separates local removal vs actual owner gallery delete. |
| Owner workflow | Configure assistant / respond to requests / approve visits | `/owner`, `/owner/listings/[id]` | Correct manual-approval boundaries; welcome/permission guidance could be more prominent for logged-out owners. |
| Two-party transaction | Understand proposals vs agreed facts | Deal room -> Jiptok prompt -> conditional card -> two-participant same-version acknowledgment | Strong core differentiator. Ensure actual recordings show first-only vs both-confirmed clearly. |
| Registry | Understand documented rights and unknowns | `/registry/extract` -> `/registry/check` | Local PDF is a privacy advantage; the UI must never overstate missing OCR/cancellation or legal verification. |
| International judge | Understand a 3-minute full product demo | `/showcase?lang=en` + KR/EN nav | Core judge walkthrough is translated; transaction data-entry remains Korean-first. Labels must say so honestly. |

## Resolved with evidence
- **P0 — Duplicate photo upload after registration:** PR #43 keeps one mounted photo editor across form save and offers publication immediately afterward.
- **P0 — Implicit AI suggestion becoming a listing fact:** PR #43 requires owner confirmation; it persists selected options after listing save with an authenticated PATCH, reporting failures.
- **P0 — Delayed AI consent location:** PR #43 displays Vision and Image consents above individual action buttons; no call on merely adding/selecting a file.
- **P0 — Misleading published-image removal:** PR #45 disables local draft deletion for published images and routes to the owner gallery delete operation.
- **P0 — Database cold-start race:** PR #42 serializes Postgres migrations across serverless instances; live production error recurrence remains a monitoring obligation.
- **P1 — English judge onboarding:** PR #44 adds KR/EN nav + bilingual showcase, maintaining Korean-first transactional workflows.
- **Regression:** Current PRs use verify-fast and verify-e2e (desktop/mobile). Production version requires an additional smoke check after automatic deployment.

## Visual QA checklist (not falsely marked PASS)

- [ ] Photo Studio cards: filename, room badge, AI disabled reasoning, two distinct consents, image comparison and privacy mask work on mobile.
- [ ] After save: no lost photo state, separate publication consent, successful gallery POST; reload limitation explained.
- [ ] Post-publication: remove action does not silently imply remote delete; owner gallery provides actual delete.
- [ ] Owner hub: signed-out and signed-in first-time user know next action.
- [ ] Buyer room: two confirmed states distinguish pending vs mutual agreement, with source evidence.
- [ ] Registry: results do not imply automatic ownership confirmation or legal safety.
- [ ] Production deploy SHA, health, image URLs and `/showcase?lang=en` verified after merge.
- [ ] Demo video remains <180 sec, publicly accessible, no external model/asset misrepresentation.

## Main recommendation
Do not add more AI features before the submission. Finish the photographed user journey, captions/narration and real-model evidence. Judges are more likely to value one reproducible owner-to-buyer story than a sprawling menu of disconnected prototypes.
