# P16 | DirectHome 해커톤 통합 시연 및 AI 평가 가이드 (2026-11-02)

## 0. 시연 목적
**핵심 사용자 가치:** 복잡한 한국 부동산 직거래에서 (A) 집주인이 매물을 등록·응대할 때의 반복 업무 감소, (B) 집을 구하는 사람이 확인해야 할 권리/신원 항목의 가시화, (C) 양측 대화에서 합의와 미합의를 정확하게 구분하고 다음 절차를 놓치지 않게 하는 집톡이.

이 프로젝트는 중개/가격협상/본인·소유권 인증 대행 서비스가 아닌 **AI-assisted direct trade PoC**이며, 개발 시연을 위해 합성 매물·Mock 모델·공개 교육용 등기 PDF를 사용한다. Mock 테스트 통과가 실제 Meta 모델 품질이나 법률 적합성/실사용자 안전을 증명하지 않는다.

## 1. 앱 안에서 직접 따라가는 경로
공개 페이지 /showcase 에서 소유자·집을 구하는 사람·등기부 체험을 선택한다. 해당 페이지는 실제 구현된 기능의 링크를 제공하는 정적 가이드이며 조회 자체는 모델 API 호출·개인정보 입력·서버 쓰기 요청이 없다.

### 소유자 | 등록 → 사진 → AI 임대인 → 방문
1. /register 에서 등록 마법사 5단계. 실제 가입·소유자 권한 필요. 등기 PDF에서 단순 주소·면적 초안 로딩을 선택적으로 이용하되 실제 소유권 검증으로 표현하지 않음.
2. 사진 도우미: 사진의 누락 공간/옵션 **후보**를 추천. 제공 옵션은 사용자가 선택해야 최종 폼 입력. 로컬 Canvas 가림 후 별도 게시동의로 작은 JPEG 파생본만 갤러리에 저장. AI 생성 가구 제거 이미지는 실제 매물 사진으로 게시하지 않음.
3. /owner 의 작업 허브에서 반복 문의 응대 정책·가능 시간 설정. AI는 집주인의 기존 사실만 답변하며 협상/가격 결정/계약·예약 확정을 대리하지 않음.
4. 방문 예약 신청 시 집주인이 별도 승인해야 확정. 요청·취소·만료 이력과 별도 확인 사항을 작업함에서 관리.

### 방문자 | 탐색 → 권리정보 → 문의 → 조건
1. / 는 지도/리스트 탐색, 사용자 등록 사진과 합성 AI 시연 이미지 별도 표시.
2. /listings/s02 는 합성 예시 매물. 실제 매물에서는 소유권 미검증 고지·사진 갤러리·권리 후보가 공유된 경우에도 **게시자 제공·공식 검증 미완료**라는 고지 표시.
3. /registry/extract 는 공개 교육용 PDF 링크 5종을 브라우저 안의 PDF.js로 읽고, 구조 복원 및 P12 독립 행 검사 후 검토 후보를 출력. PDF 원본·이름·주소·실 권리자 텍스트를 서버/Meta로 전송하지 않음. 스캔 PDF OCR과 말소선은 아직 미지원.
4. 실제 거래방은 방문, 가격·생활 조건, 등기/대리권, 계약 준비의 4단계 중립 가이드 표시(P15); 가격은 양측 동일 버전 동의일 때만 앱 내부 confirmed. 집톡이는 가격을 중재·절충하거나 법적 계약·송금을 대신 확정하지 않음.

## 2. 평가자가 확인할 구현 근거
- AI 이중 역할: **AI 임대인**은 등록된 사실로 문의를 처리하며 수동 승인 요청/재시도; **집톡이**는 양측 대화의 조건·누락 절차를 식별하되 당사자가 아니다.
- 버전 일관성: 동일 가격/보증금+월세 조건을 하나의 카드로 관리. 일부 동의, 새 조건 변경 및 철회에 대해 무단 확정 방지.
- 등기 분석: 교육용 공개 PDF 7개 획득(5종 당당 문서 의미 게이트 5/5), HUG/HF/당당 출처 기반 부분 사실+독립 관찰 행 검사(P12), 개인정보 처리 최소화. 사람이 문서 전체에 대한 법률적 정답을 별도 라벨링해야만 개발 가능하다는 가정 제거.
- 사진 AI: 옵션/누락 공간 가이드, Meta Muse Spark/Vision 입력/출력 allowlist, 명시적 동의/저비용 호출 게이트. 가구 제거 Muse Image 시뮬레이션은 시각적 비교만, 실제 방 구조로 주장 금지. 정식 실 Meta 유료 호출/출력 품질 검증은 아직 수행하지 않음.
- 통합 기능: 시연 매물/일반 매물 구분, 소유자 게시/삭제 권한, 개인 문서 원본 로컬 처리, 권리 참고항목을 실제 상세 화면에 연결, 계약 준비 미확인 상태 자동 보존.

## 3. 재현·테스트 기록
- GitHub Actions의 verify-fast는 DB/단위/API를 isolated SQLite/모의 upstream으로 검증. verify-e2e는 desktop/mobile Playwright. 각 브랜치 head와 최종 status는 PR #25, #34(P13), #35(P14), #36(P15) 및 P16 PR 체크에서 직접 확인.
- 외부 샘플은 출처 URL·SHA256/메타데이터만 Git 저장; PDF 바이트·실거주인 사진을 저장소나 로그에 복제하지 않음.
- P16의 /showcase 첫 페이지 로드 시 모델/이미지 생성 유료 호출 없음. 실제 기능 링크를 직접 따라갈 수 있으며 로그인과 개인정보 동의가 필요한 행동은 해당 화면에서 명시적으로 처리.
- 실제 두 계정 거래의 모든 기능, 외부 PASS·토스 신원제공, 소유권/위임권한 공식 인증, 실제 법률 자문, 운영 DB 파기·백업, 스토리지 상용화는 출시 게이트로 분리.

## 4. 데모 실패 방지
- Meta 모델/유료 호출이 비활성이라도 합성 시연 매물과 권리·리스트·설명은 탐색 가능; 어떤 모델 결과를 얻었다고 허위로 발표하지 않음.
- 공개 교육용 등기 PDF 원본이 공급자 사이트에서 사라졌다면 원문 분석은 불가능. SHA pin이 다른 자료로 바뀌어도 CI는 실패; 출처 확보 실패와 파서 정확도 실패를 따로 기록.
- 계약 상대 신원·소유권을 인증했다고 주장하지 않으며, 채권최고액은 실제 대출잔액이나 법적 보증금 회수 가능성 수치가 아님.
- Owner/tenant 실제 2인 거래는 사용자 결정으로 보류. 제출문에는 이를 별도 한계로 표시.

## 5. 후속 release blockers
1. 법무/개인정보 검토, 공인 본인확인 B 및 물건 소유·임대권한 C 검증, 공개 매물 게시에 필요한 관계 법령.
2. 사진 DB 저장 → 비공개·접근통제형 객체 스토리지 이전, 개인정보 삭제/접근통제/백업 처리.
3. 실사용자 2인 QA, 실제 Meta Muse Spark/Vision/Image 모델 출력 품질·비용·개인정보 약관 검증.
4. Vercel production deployment SHA와 PDF worker same-origin 전달, 운영 Cron·백업/장애 대응.
