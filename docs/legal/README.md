## 보관용 과거 문서
[법률 쟁점 1차](LEGAL_REGULATORY_REVIEW_20261101.md)는 당시의 사고 과정과 정정 기록을 보존하려고 남겼다. **현행 검토는 심층 감사 v2를 우선**하며 특히 '등기부 PDF가 전송 전에 마스킹됐다'는 초판 설명이 오류였다는 사실을 반드시 확인할 것.

## 절대 혼동하지 않을 구분
- **일반인 등기부 열람 가능** ≠ 대량 등기정보 제공·모든 재판매·국외전송 허용.
- **로그인 계정 확인** ≠ 공인 본인확인(B) ≠ 물건에 대한 소유·위임권한 검증(C).
- **채팅에 나온 제안** ≠ 같은 버전의 두 사람 동의 ≠ 법률상 계약의 체결/유효성 확인.
- **집톡이의 다음 절차 안내** ≠ 플랫폼이 거래를 알선·협상·대리하는 행위.
- **권리관계 체크리스트** ≠ 최신 등기 확인·권리순위 검증·보증금 회수 보증.
- **합성 시연 PDF 분석** ≠ 실제 등기 PDF 분석 및 Meta 개인정보 전송의 법률적 허가.
- **CI PASS** ≠ 외부 업체 실계약·실서비스/운영 DB 검증·변호사 법률의견·법률 준수 완료.

## 개발 로그 규칙 (앞으로도 유지)
1. 신규 단계마다 별도 브랜치/PR과 하나의 `docs/Pn_*.md` 기록 파일을 만든다.
2. 발견한 법률 근거는 조문·판례·시행시점·원본 링크를 기록한다. 검토 시점과 미확정 사실을 명시한다.
3. 코드수정/테스트/실행 결과/실패 수정/후속 목록을 `DEVELOPMENT_LOG.md`에 남긴다.
4. 법률 이슈를 CLOSED로 바꾸려면 검토 주체·증빙·시행일·운영환경·수정 커밋을 남긴다.
5. 여러 작업을 묶어서 진행해도 **배포·법률 승인·인증기관 승인**과 PoC 코드 병합을 구분한다.

## 후속 조사 필요
등기정보 업체 취득/재가공 계약, 광고 필수 항목/2026~2027 시행령, 개인정보 보유·파기·위탁/국외이전, 법률상 거래 알선 판단, 실제 본인확인기관 연동, 사업자 수익모델, 운영자 신고 후 조치. 사용자 요청으로 **실사용자 2인 실제 거래 테스트는 보류**.
