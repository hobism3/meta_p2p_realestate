# 집톡이 거래 진행 워크플로 (시연 UX 설계)

목표: 집톡이는 그룹채팅에서 임대인/매도자와 임차인/매수자 사이의 **합의 상태 및 미완료 절차를 관리**한다. 가격 중재·절충안을 제안하지 않는다.

## 대화 → 근거 → 거래 조건 → 합의
1. 사용자와 시연 AI 임대인의 발화에서 제안 내용과 원본 메시지 ID를 추출한다.
2. 매매가는 하나의 값, 월세는 '보증금 X만원/월세 Y만원' 원자적 묶음으로 관리한다. 한쪽 제안은 협상 이력이지 확정이 아니다.
3. 임대인이 제시한 조건에 임차인이 '전 좋아요'로 명시 수락하면 바로 앞의 구체적 임대인 제안에만 연결한다. '방 보고 왔는데 좋네요' 같은 집 평가를 가격 수락으로 해석하지 않는다.
4. 반려동물 허용은 매물 고정 옵션이 아니라 **거래 중 새로 합의할 옵션 조건**으로 기록한다. 임대인의 실제 허용/제한 발언이 근거다.
5. 양측이 같은 가격·날짜·추가 조건을 확인할 제안 카드가 채팅에 붙는다. 카드에서 각자의 동의가 기록되어야 상태가 '양측 동의'가 된다.
6. 카드 양측 동의가 완료될 때만 집톡이가 다음 절차를 그룹채팅 메시지로 안내한다.

## 공통 진행 순서
집 확인/방문 → 가격 합의 → 옵션·특약 확인 → 계약 일정 → 계약금 → 잔금·인도/입주. 이 순서는 가이드이며 거래별로 일부 단계가 생략되거나 순서가 달라질 수 있다.

## 거래유형별 차이
- 매매: 가격 및 권리관계 확인 후 계약일·가계약 필요 여부를 논의한다. 가계약은 필수 절차로 표시하지 않는다. 본계약·계약금·잔금일·소유권 이전/인도 관련 준비를 안내한다.
- 전세: 전세보증금, 특약·주거 옵션·입주일, 계약일, 계약금, 잔금/인도 일정을 안내한다.
- 월세: 보증금/월세 두 값을 하나의 조건으로 확인한다. 관리비, 반려동물 허용, 시설·수리 조건, 계약일, 계약금, 잔금·입주를 차례로 확인한다.

## 미확인/보류
'동의 대기', '제안됨', '양측 동의'는 서로 다른 상태다. 상대의 허용 발언만으로 당사자 합의를 만들지 않는다. 제안이 바뀌면 이전 승인을 재사용하지 않는다. 대화상 날짜가 모호하거나 서로 모순되면 실제 방문/계약 확정으로 표기하지 않는다.

## 기존 대화 복구
'기존 대화에서 빠진 조건 다시 정리'는 명시적 POST 액션이며 시연방 회원에게만 허용한다.
서버 mock 규칙을 사용하여 저장된 최근 대화의 근거로 누락 후보를 복원한다. 과금형 Meta를 추가 호출하지 않는다.
동일 방·동일 마지막 트리거에 대한 재정리는 별도 실행 유형으로 유일하게 저장하여 반복 처리되지 않는다.
과거 합의의 동의 완료 판정은 소급 생성하지 않고, 확인 카드를 새로 만들었다면 당사자가 직접 동의해야 한다.
