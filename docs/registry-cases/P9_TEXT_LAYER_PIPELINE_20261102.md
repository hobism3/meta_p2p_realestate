# P9 — 등기 PDF 텍스트층 → 근거 후보 → 사람 검토 → P8 분석 (2026-11-02)

## 0. 문제/절대 목표
P8에는 출처가 기록된 **38개 가상 권리 해석 골든**이 있다. P9는 그 앞에 *문서에서 관찰 가능한 사실을 구조화할 수 있는지*를 추가한다.

**원본 PDF → 텍스트 추출(증빙 위치 유지) → 등기목적행/말소 행/채권최고액 분리 → 후보 신뢰 경계 → 사용자가 PDF와 대조 → P8 현행/말소 분석**.

현재 P9의 운영 브라우저 경로는 **PDF 파일 자체를 자동 OCR하지 않는다**. 개인정보 포함 실 PDF를 외부 AI/서버에 보내는 대신, 사용자가 PDF 뷰어에서 선택한 글자를 붙여넣어 로컬에서 후보를 추출한다. 개발자용 선택적 **로컬 PDF 텍스트층 추출 도구**를 별도로 제공한다. 두 경로 모두 이미지 스캔본 OCR이나 PDF 진위 검증은 아니다.

## 1. 왜 PDF 업로드를 곧장 Meta에 넘기지 않는가
- 실제 등기사항증명서에는 소유자명·권리자명·주민번호 일부·주소 등 식별가능 정보가 포함될 수 있다. 공개 열람권과 외부 상업처리/국외 AI 전송의 적법성은 별개다.
- 기존 등록용 `RegistryImport`는 **정확히 일치하는 허구 PDF 해시**만 Meta 전송을 허용한다. 이번 P9는 그 엔드포인트/정책을 변경하지 않고, 순수 브라우저 메모리만 사용한다.
- 객체 URL로 PDF를 **해당 브라우저에서 열어보는 것**은 서버로 보내는 행위가 아니다. 복사한 원문은 textarea에만 있다가 화면을 벗어나거나 초기화하면 제거된다.
- 출력 `RegistryTextExtraction`의 `evidence`는 페이지/줄/갑·을구/순위번호와 *허용된 구조화 라벨*뿐이며 원본 자유문장·소유자명·권리자명·주소를 복제하지 않는다.
- 사용자가 명시적으로 선택한 후보만 `sessionStorage`로 **한 번** 전달한다. 세션에는 allowlist 권리종류/상태/순위번호/등기일/채권최고액만 들어가며 원문 PDF·복사 텍스트/성명·주소/모델 프롬프트는 없다.

## 3. 보수적인 추출 원칙
- **모든 후보는 status=unknown, reviewRequired=true**. 추출기의 '말소 언급 연결'은 말소로 확정되는 신호가 아니라 **원문 확인 필요** 경고다.
- `등기목적` 칸 이외의 설명/권리자 칸에 등장한 `근저당` 단어만으로는 후보 생성 금지.
- `채권최고액`이 명시된 경우만 금액 후보 추출. `보증금`·`청구금액`·주소의 숫자·대지권 면적 등을 채권최고액으로 취급 금지.
- `금120,000,000원` ↔ `12,000만원`, `금1억2천만원` ↔ `12,000만원`처럼 완전한 정수 만원 단위로 변환할 수 있을 때만 기록. 만원 미만이거나 애매하면 null.
- 섹션/행 번호/날짜/금액 맥락이 없으면 **추정하지 않음**. 원문 취소선·셀병합·복수 페이지 등 레이아웃이 복사 텍스트에서 사라질 수 있음을 항상 고지.
- 페이지번호는 `[PAGE N]` 마커가 있거나 오프라인 도구가 추가한 경우에만 신뢰한다. 붙여넣기 텍스트에 없으면 line-only 근거.
- 단순 텍스트 인식률과 위험분석 품질을 구분한다. parse fail이 안전한 권리관계란 뜻이 아니다.

## 4. 사용자 흐름 (PoC)
1. `/registry/check`에서 `/registry/extract` 이동.
2. PDF 파일을 브라우저 로컬로 열기(선택) 또는 사용자가 직접 텍스트층 복사.
3. 텍스트를 붙여넣거나 테스트 사례 15종 중 하나를 선택, '권리기재 후보 찾기' 클릭.
4. 각 후보에 **허용된 정형화된 사실과 페이지/줄 근거만** 표시.
5. PDF 원문을 다시 확인하고 **원문에서 현행/말소/효력 불명 상태를 선택**, '원본과 대조했습니다' 직접 체크.
6. 선택한 자료만 sessionStorage로 한 번 전달해 `/registry/check`에서 기존 `reviewRegistryRights` 규칙으로 추후 확인사항 표시.
7. 원본을 닫고 복사 텍스트를 삭제. 현재 PDF 자체/텍스트는 서버/Meta로 전송하거나 저장하지 않는다.

## 5. 로컬 PDF CLI (개발자·실험자용)
PDF 뷰어의 복사기능이 불편한 경우에 한해 다음을 사용한다. 실행 주체의 로컬 PC에서만 동작:
~~~sh
python -m pip install pypdf
python tools/registry_pdf_text_local.py /local/path/synthetic.pdf --output /tmp/local-registry-text.txt --allow-sensitive-local-output
~~~
- 출력은 민감한 원본 텍스트일 수 있으므로 Git 내부에 만들 수 없게 차단하고 0600 파일로만 생성. 기존 파일 덮어쓰기 금지.
- stdout에는 페이지 수·문자 수만 표시, 원문 내용 출력 안 함.
- 스캔·암호화·파손·너무 큰 PDF에는 실패. **OCR이나 인쇄된 취소선 검출은 아님**.
- 파일을 GUI에 붙여넣은 다음 로컬 출력 파일을 삭제해야 한다. 자동 보관/파기는 하지 않는다.

## 6. 공개 원문 조사와 실제 검증 범위
- 당당 [등기 문서 가이드](https://dangdang.io/blog/registry-document-guide)의 **교육용 가상 PDF** 5개 링크를 찾았으나 Web 원문 다운로드에서 Cache miss가 반복되어 이번 P9의 실제 PDF 텍스트층 정답으로 삼지 않았다.
- [국립아동권리보장원 주거 안내 PDF](https://www.ncrc.or.kr/upload/ncrc/03.jugeo.pdf)는 웹에서 내용과 등기사항증명서 예시 표기를 확인했다. 그러나 PDF **페이지 이미지 스크린샷 기능도 Cache miss**로 실패하여 시각적 1:1 원문 검증을 완료하지 못했다.
- 이 문서의 15개 P9-Txx는 실제 외부 PDF의 문자 추출 결과가 아니라 위 공적/교육용 구조를 참고해 **독립 작성한 합성 텍스트 예시**다. '실 PDF 인식 정확도'로 광고하거나 CI를 이를 검증한 것으로 표시하지 않는다.

## 7. 향후 다음 단계
- 본인/권리자 식별정보를 적법하게 처리할 수 있고 재이용 허가된 **합성 PDF 원본을 확보**하여 PDF 페이지별 텍스트→그리드 좌표/취소선 구분→골든 라벨 평가.
- 정확도 평가를 `row detection recall`, `section accuracy`, `kind precision`, `claimMaximum exact match`, `cancellation link accuracy`, `unsupported/fail-closed rate`로 세분화.
- 브라우저 PDF 자동 텍스트층 인식은 **검증 가능한 로컬 PDF 라이브러리를 번들링**할 수 있을 때 추가. 공용 CDN에서 민감 PDF를 실행하는 방식이나 PDF 원문 외부 Meta 전송을 우회하는 방식은 도입하지 않는다.
- 사진 VLM PR #25는 별개 책임/코드. 집 사진으로 근저당·소유권·신탁 효력을 추정하지 않는다.
