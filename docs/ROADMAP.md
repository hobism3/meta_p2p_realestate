## 데이터 규약 (불변)
- 방문: 실제 예약 확정은 `owner_visit_bookings.status='confirmed'` 뿐. 시연/과거 `visits`와 혼합해 확정하지 않는다.
- 금액·옵션: `room_proposals.status='agreed'` + 동일 버전의 양측 명시 동의만 확정. 대화·AI 추출·집주인 단독 허용 발언은 후보.
- 반려동물: 매물 원본 옵션과 **이 거래에서 허용된 생활 조건**을 구분.
- 진행 단계: AI는 DB 상태로부터 다음 미확인 항목을 추천, 절충안이나 계약의 법적 효력을 창출하지 않음.
- 거래별 분리: JWT sub, listing owner_id, room membership 경계를 모두 지킨다.
- 데모/실거래: 시연 AI 임대인의 가상 동의와 실제 집주인의 동의는 별도.

## 개발·검증 운영
1. 한 단계마다 작업 브랜치/PR을 만든다. 설계·테스트·DB 정책을 함께 커밋한다.
2. 새 DB migration은 기존 사용 데이터와 호환하도록 additive/compatible하게 구성한다.
3. `npm run build` + node 단위·API 통합 + Playwright PC/모바일 + GitHub verify-fast/e2e + Preview READY 확인 후 main에 병합한다.
4. main 병합 SHA, Production READY, 재현 가능한 검증을 `DEVELOPMENT_LOG.md`에 기록한다.
5. 외부 알림·네이티브 앱은 후속. 웹만으로 완결되는 거래를 먼저 검증한다.
6. 테스트 계정 실제 생성은 Supabase Admin 권한/본인 소유 이메일이 필요. 합성/비운영 테스트와 실운영 수동 검증을 구분한다.
