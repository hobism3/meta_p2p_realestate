## C. Golden 테스트의 정답·평가 체계
`registry-cases.v1.json`의 각 `case`에는 다음이 들어간다:
- `id`: 영구 시나리오 ID (`P8-001` … `P8-038`)
- `sourceIds`: 재현 근거가 된 공식/블로그 출처의 ID
- `provenance: synthetic_derived_pattern`: 실제 문서 전사 아님
- `detectability`: `title-record` / `data-quality` / `cross-document` / `outside-registry` / `timing` / `composite`
- `input`: 프로덕션 `reviewRegistryRights`와 동일한 구조(권리 종류·날짜·상태·채권최고액 등)
- `expected`: 사람이 독립적으로 기록한 예상 **발견 ID·제외 ID·현행 근저당 건수·합산 가능 금액·누락/말소/미확인**. 엔진 출력을 정답 데이터로 덮어 쓰면 안 됨.
- `note`: 출처의 핵심 주의점 또는 엔진 바깥에서 요구되는 별도 사실.

### 반드시 거절해야 할 잘못된 결론
- 근저당 채권최고액 = 실제 대출잔액 또는 보증금 회수액이라고 주장.
- 등기부의 을구에 아무 것도 없으면 타 채무/세금/선순위 임차인도 없다고 추측.
- 같은 임대인이 말로 근저당·신탁을 '지우겠다'고 하니 이미 말소됐다고 표시.
- 공동담보를 여러 부동산에 일률적으로 배분하거나 여러 건이라고 채무를 기계적으로 중복 합산.
- 소유자 이름만 보거나 Google 로그인만 했으니 실제 임대 권한 인증완료로 표시.
- 부동산 문서에 없는 시세·대항력·점유·세금·배당순위를 임의로 채워 '안전' 판정.
- 블로그의 임의 비율(60%, 70%, 80%)을 **법적 안전 기준/보증 가입 기준**으로 하드코딩.
- 합성 테스트 PASS를 실 PDF 추출/OCR·VLM·법률 검증 PASS로 둔갑.

## D. 실제 교육용 PDF/이미지 사례는 어디서 구하나?
- 당당 위 원문에 정상, 가압류, 근저당, 복합 위험, 확정일자 설명용 **가상 PDF 링크**가 있다. 지금 단계에서는 해당 파일을 Git 저장소에 복사하거나 실제 법원 증명서로 혼동하지 않고 **원본 링크를 통해 외부 자료로만 참조**한다.
- 진짜 등기사항증명서는 대법원 인터넷등기소에서 누구나 발급 가능하지만, 고객·타인 개인정보 포함 원본을 자동으로 수집하거나 Meta로 전송하지 않는다.
- 별도의 추출 벤치마크가 필요하면 **정상적으로 사용/재배포가 허용된 허구 PDF**, 출처/버전/원본 해시/정답 라벨, 로컬 비식별 처리, 누락·오기율 검증을 확보한 후 추가한다. 이 38건은 **문서 인식 성능 평가가 아니라 권리 해석 정책 회귀**다.

## E. 새 자료를 추가하는 규칙
1. 새 문서의 출처 URL, 공적/민간, 실제 사건 소개/교육용 허구/연구용 합성 여부, 발행/확인일, 핵심 주장·해석 한계를 기록한다.
2. 법률 결론 대신 **등기부에 적힌 사실(관찰)**, **거래 시점에 필요한 다른 자료**, **불확실성**을 분리한다.
3. 이름·주소·주민등록번호·권리자 ID·PDF base64는 테스트/코드/로그에 수집·커밋하지 않는다.
4. 새 `P8-xxx`를 추가하면서 최소 1개 예상 발견·제외 ID 및 수치 불변식·근거 링크를 기록한다.
5. 시뮬레이션 fixture로 합성 입력을 만들되, 모델/정책 코드를 변경하지 않고도 독립 기대값을 기록한 다음 CI에서 비교한다.
6. 실패는 오탐(false positive), 누락(false negative), 근거 부족(insufficient)으로 분리하고 **기존 정답을 조용히 완화하지 않는다**.

## F. P8 이후 구현 후보 (외부 시각 기능과의 관계)
- P8은 등기/계약 관련 **법률 사실·권리 해석 정책**의 검증 모듈이고, 별도 `feat/visual-listing-guide-20261101`은 **실내사진 기반 매물등록 품질/촬영 가이드** 전용.
- 사진 segmentation/VLM에서 얻는 '거실·침실·욕실·촬영각도' 등은 등기부상 **소유권·담보·임대 권한을 증명하지 못한다**. 사진 모델의 결과는 매물정보 후보값으로만 사용한다.
- 추후 등기부 OCR/VLM이 생기면 `observations ` (문서 영역/원본 문자열/신뢰도·근거 좌표) → **정형 `RightEntry` 후보** → 사용자/규칙 검증 → `reviewRegistryRights` 순서의 별도 계약이 필요하다. OCR의 추출 confidence가 법적 효력의 probability를 뜻하지 않음을 명시한다.
