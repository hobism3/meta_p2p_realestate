# P15 | 집톡이 통합 거래 진행 UX (2026-11-02)

## 제품 목표
당사자들이 한 거래방에서 방문 예약 → 가격/생활 조건 양측 확인 → 등기·상대방 권한 확인 → 계약·잔금·입주 준비까지 무엇이 완료됐고 무엇이 아직 확인되지 않았는지 파악하도록 한다.

## 구현
- 기존 읽기 전용 TransactionSnapshot(서버의 저장된 상태)을 기준으로 화면에 4단계 안내 생성. 방문/조건 상태는 오직 집주인의 실제 예약 승인 및 동일 버전 양측 확인 카드에서만 확정.
- 집톡이는 가격을 흥정하거나 임대인 대신 제안하지 않고, 남은 일을 안내하고 관련 화면으로 이동시킨다.
- 거래방 TransactionProgressPanel에 '집톡이가 챙기는 다음 단계' 요약. 방문은 예약 패널 앵커, 조건은 양측 확인 카드, 등기·신원은 해당 매물 상세의 권리 안내 영역, 계약 준비는 관련 조건 카드와 독립적인 서류 확인 안내.
- 누구나 확인했다고 주장하더라도 등기·본인·소유권·위임권한·선순위·체납 및 계약 법률 효력/송금 확인 단계는 자동 완료하지 않는다. '앱 내 양측 가격 조건 확인'은 법률상 계약 체결·서명이 아니다.
- 기존 buildCompanionTasks의 일반 /registry/check 링크는 해당 거래 매물의 권리 확인 안내로 대체(매물 ID 있는 경우); 서버의 거래방 인증을 통해서만 매물 ID를 취득한다.
- web/lib/transaction-journey.ts는 LLM/유료 호출 없는 순수 프레젠테이션 함수. DB 상태 변경 없음.
- web/tests/transaction-journey.test.mjs: 예약 보류, 일방 제안, 양측 합의, 변경 제안, 등기 미확인, 잘못된 매물 ID 회귀. 기존 verify-fast에 추가.

## 남은 검증
실제 Supabase 두 계정 거래, 본인확인기관, 정식 법률자문, 개인정보 파기, 푸시 알림, 전자서명·에스크로 미구현. 앞선 P14에서 공개된 권리기재는 게시자의 미검증 후보이며 공인 확인 상태가 아니다. 자동 E2E를 실제 법적 효력 검증으로 혼동하지 않음.
