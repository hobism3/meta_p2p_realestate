# 집톡이 · 등기정보 접근, 재이용, 자동 분석의 법률·기술 검토
기준: 대한민국, 2026-11-01. 최신 법령·사업자 계약·개인정보보호 실사 결과가 아닌 **공식 출처 기반 사전 검토**.

## Executive finding
**부동산등기법 제19조 제1항은 '누구든지' 수수료를 내고 등기기록의 전부 또는 일부 열람, 등기사항증명서 발급을 청구할 수 있다고 규정한다.** 소유자·임대인만 등기를 볼 수 있다는 주장은 틀리다. 그러나 그 규정은 모든 상업적 크롤링·제3자 재판매·개인정보 DB 무기한 저장·외국 AI 서버 국외이전까지 일반 허가하는 규정은 아니다.

### 법률적으로 서로 다른 행위
|행위|근거/설명|집톡이 설계 판정|
|---|---|---|

## 1. 공적 열람권: 정확한 범위
- 법적 근거: `부동산등기법 제19조 제1항`. 제3자라도 수수료 납부 후 등기기록에 기재된 사항의 전부/일부를 열람하거나 증명서 발급 청구 가능. 신청서·원인증서 등 **등기기록 부속서류**는 원칙적으로 이해관계 있는 범위에서만 열람.
- 대법원 `인터넷에 의한 등기기록의 열람 등에 관한 업무처리지침` 제2조에서 등기기록 인터넷 열람, 등기사항증명서 및 전자증명서 발급, 선택적 부속 문서 열람의 방법 구분. 열람 기록이 최신 상태인지, 말소사항 포함/현행 유효사항 여부와 함께 확인.

- 지침: https://www.law.go.kr/LSW/admRulLsInfoP.do?admRulNm=인터넷에+의한+등기기록의+열람+등에+관한+업무처리지침&docType=JO&joNo=000900000&languageType=KO&paras=1
- 공식 인터넷등기소: https://www.iros.go.kr

### 매우 중요한 추가 법조문: 부동산등기법 제109조의2 (일괄 데이터 제공)
**제19조와 구별해야 한다.** 제19조는 누구나 **개별 등기기록의 열람·증명서 발급을 청구**하는 규정이다. 한편 **제109조의2 제2항**은 행정기관이 아닌 자의 **등기정보자료 제공**을 정하면서, 등기명의인별로 작성되었거나 등기명의인을 알아볼 수 있는 자료는 법률상 특별한 예외가 없으면 **해당 등기명의인 또는 포괄승계인만 제공받을 수 있다**고 규정한다. 따라서 일반 개인이 개별 주소로 등기사항증명서를 발급받을 수 있다는 사실만으로, 사업자가 임의 주소 수십만 건의 이름 식별가능한 등기정보를 법원에서 일괄 제공받고 재판매할 권리가 있다는 결론은 **성립하지 않는다**.
- 공식 법조문: https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=02&joNo=0109&lsiSeq=265377&urlMode=lsScJoRltInfoR
- 대법원규칙 「등기정보자료의 제공에 관한 규칙」 제정 목적은 개인정보보호와 데이터 활용의 조화, 명의인별 정보와 비식별 정보 제공 차등 규정: https://www.law.go.kr/LSW/lsRvsRsnListP.do?chrClsCd=010202&lsId=013805&lsRvsGubun=all
- 법원 공식 안내로 확인되는 Open API는 일부 공시·통계·등기기준 실거래 데이터다. **원본 등기사항증명서 전체 제공 API로 혼동 금지**: https://www.g.scourt.go.kr/judiciary/information/public/index.html
- 민간 에이픽은 2025-02-13 등기사항증명서 API와 열람·다운로드 단계가 있다고 공개적으로 공지하였다. 이는 제품 존재의 증거일 뿐, 법원 공식 제휴 지위, 모든 재가공/재판매/국외이전 허용, 대량 자동화 약관 준수의 증거는 아니다: https://apick.app/user_notice/28

**이용허가 확인 방법:** 업체에 (1) 각 요청별 증명서 열람/발급 대행의 법률·약관 준수 경로인지, (2) 등기정보자료 일괄 제공 제109조의2의 허용 범위를 따르는지, (3) 이용약관상 상업적 재가공/보존/재제공/AI 외부전송 권리와 개인정보 처리 근거를 **문서로** 제출받아야 한다. 일반 열람을 통한 개별 자동화의 적법성도 운영 형태/약관/접근수단에 따라 별도 검토가 필요하다.

## 2. '누구나 뗄 수 있다' ≠ 개인정보 무제한 상업처리
- 등기정보의 가용성과 개인정보 처리 적법성은 **서로 다른 법률 문제**. 공개기록의 소유자명과 주소가 개인 식별가능한 정보이면 개인정보가 될 수 있다.
- 개인정보 보호법 제15조는 동의 외에도 법령에 특별한 규정, 계약 이행, 정당한 이익 등 **다양한 적법 근거**를 인정한다. 따라서 **개별 소유자 동의가 없는 모든 등기정보 활용이 자동 불법**이라는 단정도 부정확하다. 반대로 '공개 등기니까 제15조 적용 없음'도 오류.
- 목적·항목·보유·공개대상·정보주체 기대·이익형량·필요 최소성과 제3자 권리를 검토해야 한다. 특히 정당한 이익(제15조1항6호)은 정보주체의 권리에 명백하게 우선하고 합리적인 범위를 초과하지 않을 때만 검토 가능.
- 주민등록번호는 제24조의2에 따라 단순 동의만으로 자유롭게 수집할 수 있는 정보가 아니다. **집톡이 DB, 로그, LLM 프롬프트에 적재하지 않는 설계**가 기본.
- 다른 제공자에게 문서를 전송하면 제17조/제26조의 제3자 제공·위탁 구분, 제28조의8의 국외이전 요건이 추가된다. **업로더 1명의 동의만으로 문서의 모든 권리자 개인정보에 대한 근거를 자동 확보했다고 보지 않는다**.
- 근거: https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1029334879 ; https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335661 ; https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1034515803

### 구체적인 처리 방식
A. 이용자가 임의 주소를 입력 → 등기 내용의 사실관계만 확인하고 **소유자명/주민번호/권리자 연락처를 외부 공개하지 않음**.
B. 서비스 검증을 위해 일시 이용 → 원본 보존 필요성/법적 근거/파기 기한이 확인되지 않았다면 영구 저장 금지.
C. AI 분석 → 필요한 제한적 비식별 필드만 전달 가능하도록 데이터 흐름 설계. **단순 PDF 검은색 덮기, 파일 이름 'redacted', 응답 결과의 필터링은 안전한 비식별화가 아니다**.
D. 모델 학습·재제공 → 별도 계약 및 개인정보 적법성 확인 전 불허.

## 3. '등기부 API를 파는 회사도 있다' — 확인 결과
실제로 `에이픽(APICK)`에서는 부동산 등기사항증명서 열람·발급 API를 상품으로 소개하고, `등기고`는 부동산 등기 조회·변동 알림 개발자 API 문서를 제공한다.
- https://apick.app/
- https://apick.app/user_notice/16
- https://deunggigo.kr/api-guide
- **중요:** 벤더가 상품을 팔고 있다는 사실과 해당 벤더가 법원으로부터 특정 재이용/재판매 허가를 받았다는 것은 다른 문제. 구매한다고 사용자 개인정보의 **자동 국외전송·공개·재판매 권리**가 자동 발생하지 않는다.
- 등기정보광장 공식 Open API는 분석·통계·등기기준 실거래가 등도 제공. **특정 주소의 완전한 등기 원문을 같은 방식으로 받을 수 있는 공식 API가 공개되었다고 단정하면 안 됨**.
- 공식 사법부 안내: https://www.g.scourt.go.kr/judiciary/information/public/index.html

### 유료 제공업체 실사 필수 질문(계약서 증빙 요청)
1. 원본 제공 주체 및 등기서류 취득 경로: 공적 열람/제휴/자동화 중 무엇인가? 약관 위반·대량 수집 제한은 없는가?
2. 제공 원본: 열람용 화면, 증명서 원본, 단순 파싱 JSON, 샌드박스 모의 응답 중 무엇인가? **실제 데이터인지** 검증 자료 요구.
3. 자료 재이용: 소유자명 등 개인정보 수집·가공·저장·재제공과 해외 AI 모델 전송을 계약이 허용하는가?
4. 등기부 최신성: 발급 시각, 처리 중 등기 여부, 말소사항 포함, 신탁원부·공동담보 목록을 반환하는가?
5. 증거성: 원본 발급 기관/문서 식별자/진위확인/해시/요청 시간 추적이 가능한가?
6. 삭제·보관: 공급자 로그와 DB의 원본·파생물 보관기간·삭제 재현·하위수탁사·국외 이전 지역은?
7. 보안/운영: API 키 권한·IP 제한·쿼터·단위요금·타임아웃·실패 시 결제/환불·취약점 신고·계약상 책임은?
8. 개인정보처리자/수탁자/제3자 관계, 정보주체 권리행사·유출 통지·데이터유출 계약책임은?

### 추천 아키텍처 (법률/계약 확인 이후)
주소/동·호 정규화 → 공식 또는 계약된 API에 요청 → 발급일·원본 해시·데이터 출처 수집 → 신뢰된 로컬 권리내역 파싱 → **허용 목적에 필요한 요약만 DB** → 집톡이는 *권리 위험요소 설명·추가 확인 항목*을 제공. 권리자 원문/주민번호는 프롬프트/공개 API에서 제외. 등기부에는 나타나지 않는 세금·선순위 임차인·위반건축물·현장 상태는 별도 검증 목록으로 남겨둔다.

## 4. 등기부만으로 '게시자=소유자' 인증되지 않는 이유
- Google/이메일 로그인은 해당 계정의 서비스 로그인만 증명. 실명·권리관계 인증 아님.
- 등기부의 소유자 이름이 같아도 동명이인 가능; 주민번호 일부 마스킹/동일 성명은 고유 신원 증거가 아님.
- 부동산 임대권한은 등기상 소유권과 항상 동일하지 않다. 공유지분, 적법한 위임, 신탁, 임대인과 소유자 분리 등이 존재. '명의가 다르면 무조건 사기'는 부정확.
- 필요한 것은 **본인확인(신원 주체 확인) + 그 부동산에 대한 관계/권한 확인 + 원본 출처/시점 + 위임 진위/범위 확인**의 별도 증거사슬.
- 사용자 자기진술만 가능한 현 단계에서는 `관계 자기진술/독립 검증 미완료`를 분리 표시한다.
- 공식 지자체 체크리스트: https://www.anyang.go.kr/main/contents.do?key=4349

## 5. 등기부 위험 분석에서 제공할 수 있는 것 / 금지할 것

## 7. 결론
공개 등기제도를 집톡이가 활용하는 것 자체를 부정할 법적 근거는 없다. *누구나 열람 가능*한 공시제도를 바탕으로 거래 안전성 확인 도구를 만드는 방향은 합리적으로 검토할 수 있다. 다만 **취득 절차·API 이용 계약, 개인정보 최소화·국외전송, 권리/사실과 법적 안전 판단의 분리**를 거쳐야 한다. 이 문서만으로 벤더 계약·개인정보 처리 적법성/서비스 출시 승인은 하지 않는다.
