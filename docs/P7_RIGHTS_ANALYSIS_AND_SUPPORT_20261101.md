## 1. 왜 이번에는 권리관계 분석을 구조화했나?

기존 `/registry/check`는 근저당·신탁·압류 등의 **존재 여부만 수동 체크**했다. 그러나 실제 등기사항증명서는 `현행/말소`, `표제부/갑구/을구`, `등기 접수일`, `순위번호`, `채권최고액`이 함께 나타난다. 같은 '근저당 있다'라는 말이어도 말소 여부와 금액 미입력 상태를 구분해야 하며 **채권최고액을 실제 대출잔액으로, 접수 순위번호를 법률상 최종 배당순위로, 등기부에 안 보이는 선순위 임차인/세금을 '없음'으로 판단하면 안 된다**.

이를 위한 구현 경계를 다음처럼 정함:
1. 원본 PDF·주소·소유자명·주민등록번호를 **받지 않는다**. 해당 정보는 브라우저에서도 입력 폼 없음.
2. 사용자가 직접 등기부에서 확인한 **구조화된 최소 필드**만 브라우저 메모리에서 평가한다.
3. 현행이라고 입력된 근저당 중 **채권최고액이 모두 제공된 경우만** 그 입력액을 단순 합산한다. 말소/효력 미확인 기록을 빼되 오해 방지 설명 필수.
4. 합계와 예정 보증금은 별개 참고자료. 담보가치·채무잔액·배당순위·보증금 회수 가능액 또는 안전등급 **절대 산출하지 않음**.
5. 선순위 임차인, 세금, 계약자 권한, 건축물대장 등 **등기 외 검증**은 언제나 별도 체크.
6. 발급 후 7일 경과 안내는 앱 편의 알림이지 **법률상 유효기간이나 안전 기준이 아님**.
7. 가상 예시 데이터는 명시적 '가상' 표시와 함께 제공하며 실제 등기 분석으로 포장하지 않는다.

### 권리 모델 및 중요한 원칙
- `RightKind`: mortgage, seizure, provisional_seizure, trust, lease_right, provisional_disposition, other.
- `RightStatus`: active, cancelled, unknown. 단, 사용자 입력이므로 앱이 권리 상태를 **입증**한 것은 아니다.
- 숫자 단위는 **만원**. 실사용 예시 3000은 3000만원, 24000은 2억 4000만원. 채권최고액 금액은 권리자 실제 잔액이 아니다.
- 서류 발급일 누락·미래 날짜·오래된 자료를 별도 메모로 안내. 7일은 법적 기준이 아님.
- 신탁원부, 임대 권한, 체납, 선순위 임차인, 건축물대장 등 불명확성을 숨기지 않는다.
- 사용자 입력이나 가상 예시는 `verified`, `safe`, `contract_ready` 같은 법적 의미의 상태로 승격하지 않는다.

## 3. 집톡이: '중개하는 AI'가 아닌 '다음 단계 챙기는 보조자'

현재 실거래방의 `TransactionProgressPanel`은 이미 서버의 `GET /api/rooms/[rid]/transaction-state`에서 예약·양측 확인·대화 근거를 투영한다. 새 기능은 **이 스냅샷을 읽어서 확인할 과제만 표시**한다.

- 방문 `requested`: 집주인 승인 대기. 자동 승인·확정하지 않음.
- 가격 `proposed`: 사람 양측 확인 요청. 새로운 절충 가격 제안하지 않음.
- 관리비/옵션/수리 `partial|pending`: 남은 생활 조건 확인. 집주인 매물 정보와 실제 거래 합의 구분.
- 계약일·계약금·잔금/입주: 당사자 결정/계약권한·지급 계좌 확인 필요. 전자계약·법률 효력 보증 금지.
- **권리관계 체크**는 거래 조건 합의가 끝났어도 사라지지 않음. `/registry/check` 수동 점검 링크 제공.
- **그룹채팅 메시지를 자동으로 보내지 않음**: 메신저를 차지하지 않는 보조 메모 UI.

코드:
- `web/lib/jiptok-support-tasks.ts`: 읽기 전용 `buildCompanionTasks(snapshot)` (가장 중요한 pending + 일반 다음 단계 + 권리확인 상시 최대 4건).
- `web/components/TransactionProgressPanel.tsx`: 집톡이 확인 메모 카드, 제안 카드 이동 링크, 조회 실패 시 오래된 스냅샷 지움.
- `web/tests/jiptok-support-tasks.test.mjs`: 예약·가격 pending, 새로운 가격 변경 제안, 가상/실제 스냅샷, 권리확인 상시, 최대 건수·읽기 전용 링크.

## 4. 미구현/추후 확장

- **B 실명 및 C 권한**: 실제 인증기관/등기 소유자-사용자 연결·위임장 검증 미연동. 기존 상태 유지, 시연 자동 인증 금지.
- **집톡이 메시지**: AI가 대화에 계약 또는 가격을 대신 확정·제안하는 방향은 제품 목표에서 제외. 차후 정리 내용의 증거 연결·검토 완료 여부 UX는 개선 가능.
- **법률 검토**: 본격 출시 전 공인중개사법상 거래 알선 경계와 2026~2027 광고·게시자 규제는 전문 법률 자문 필요. 문서에 OPEN 유지.
- **실사용자 2계정 실제 거래**: 사용자 요청으로 보류. Mock CI와 혼동하지 않음.
