# Stage 5 — 운영 준비와 집주인 작업함 (2026-11-01)

## 이번 배치
- 집주인 업무 요약에 인증된 소유자 범위의 **개별 작업 목록** 추가.
- 방문 승인, 직접 답변, AI 처리 실패를 개별 항목으로 표시하고 매물/유형으로 필터링.
- 각 항목에서 거래방이나 원래의 관리 패널로 이동. 이동 자체로 승인·거래 조건 합의·답변을 처리하지 않음.
- 기존 서버 서비스의 owner_id 제한 및 페이징 상한 재사용. 화면 수치는 근사적인 현재 조회 작업 수이며 누적 통계가 아니다.

## 운영 준비 체크
- [ ] Supabase의 실제 서로 다른 계정 두 개로 가입·매물 등록·질문·AI 응대·방문 승인·합의 카드 확인.
- [ ] 실제 Cron 로그에서 인증 성공, 실패 후 재시도 복구 확인. 현재 일일 Cron이므로 즉각 복구 SLA 보장 불가.
- [ ] 데이터베이스 백업/복원 절차를 별도 격리 DB에서 실제 복구 검증.
- [ ] 접근통제: 집주인 A가 B의 요청·예약·AI 실패/거래방을 볼 수 없는지 확인.
- [ ] 개인 식별정보/등기부 업로드 보관 정책, 로그 마스킹, 삭제와 보관 기간 정립.
- [ ] 외부 법률 검토 전 소유권 확인·계약 체결·법률 판단을 제공한다고 표현하지 않음.
- [ ] 비용 관리: Meta 호출 건수·에러율/토큰 예산 측정; Mock 테스트와 실제 모델 검증 구분.
- [ ] npm audit의 취약점 항목 확인 후 재현과 업데이트 영향 평가. 무분별한 force 업그레이드 금지.

## 테스트 판정
이번 PR은 변경을 한 번에 묶되 빌드/빠른 API 회귀를 필수 게이트로 유지한다. E2E는 참고하며 결함 확인 시 원인을 조사한다. 실운영 사용자·법률·보안·백업 검증은 자동 테스트 통과로 대체할 수 없다.
