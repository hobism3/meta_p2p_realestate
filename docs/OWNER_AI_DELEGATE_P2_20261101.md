# DirectHome — 집주인 AI 대리 응대 / 소유자 확인 요청 (P2)
작성: 2026-11-01. 기존 [P1 PRD](OWNER_AI_DELEGATE_PRD_20261101.md)의 2단계 구현.

## 목적과 핵심 제약
실제 집주인이 등록한 매물에 대해 **소유자가 AI를 켜고 직접 저장한 사실**만 근거로 AI 대리인이 답한다.
원본 매물 가격·면적·옵션·주소·입주일, 소유자가 지정한 반려동물/주차/추가 안내, 방문 가능 요일·시간만 자동 답변한다.
답변이 근거 없는 영역, 가격 변경, 계약·권리관계, 방문 날짜 예약 요청은 자동 확답하지 않고 소유자 확인함으로 보낸다.
**독립적인 LLM 추측형 답변이 아닌 서버측 deterministic policy engine**으로 P2 첫 버전을 구현한다.
시연용 AI 임대인과 집톡이는 별도이며 재사용하거나 임대인 본인 발언으로 위장하지 않는다.

## 사용자 흐름
1. /owner 에서 자신의 등록 매물을 조회하고 /owner/listings/[id] 에서 AI를 명시적으로 활성화한다.
2. 새로운 방문자가 매물 상세에서 거래방에 입장해 질문한다.
3. 방의 실제 매물이며 작성자가 방문자인 경우에만 `POST /api/rooms/[rid]/owner-agent/invoke` 호출.
4. 매물·집주인 정책으로 답할 수 있으면 **AI 집주인 대리인** 명의로 답변을 남긴다.
5. 확인이 필요하면 방문자에게 직접 확답할 수 없음을 알리고 `owner_ai_requests` 에 pending 요청을 만든다.
6. /owner 의 '직접 확인할 문의'에서 집주인이 답변하면 **실제 집주인 계정의 사람 메시지**로 거래방에 기록되고 요청은 answered가 된다.
7. AI를 끄면 새 문의에 자동 응답하지 않는다. 이미 생성된 요청/대화 기록은 보존한다.

## 저장·접근 통제
- `owner_ai_runs(room_id,trigger_msg_id)` 복합 UNIQUE: 같은 메시지를 재호출해도 응답 1개만 만든다.
- `owner_ai_requests(room_id,trigger_msg_id)` 복합 UNIQUE: 확인 요청 1개만 만든다.
- 조회는 반드시 `custom_listings.owner_id = JWT sub`로 제한한다.
- 답변 시에도 같은 조건을 재확인하고, 이미 answered인 요청은 거부한다.
- 자동 응대 실행은 (1) room member (2) 매물 소유자가 아닌 방문자 (3) 원본 본인 작성 사람 메시지 (4) 활성화된 AI 정책을 모두 만족해야 한다.
- 시연용 seed 매물은 계속 기존 demo agent 사용. 집톡이는 별도.
- 사람이 직접 승인하지 않은 가격 조정·예약·계약은 확정하지 않는다.

## P2 검증
- 안전한 사실 질의 / 가격 변경·계약·방문 요청 분류 / 정보 누락.
- 실제 Next + SQLite API 테스트: 소유자 토큰 분리, 직접 답변, 중복 응답 방지, 비활성화, 임의 트리거 실행 거부.
- 모바일 관리 페이지, 기존 대화방 회귀, 전체 CI E2E.

## 의도적으로 보류한 P3 기능
- **실제 방문 예약(중복 슬롯 점유, 일정 변경/취소, 확정 알림)은 아직 없음.** 현재는 방문 가능 시간 안내와 확인 요청만 제공한다.
- 외부 푸시·이메일·SMS 알림도 없음. 소유자 관리 화면의 인앱 확인함만 구현했다.
- AI가 관리자 권한으로 예약/돈/계약 변경을 실행하지 않는다.
- 향후 실제 슬롯 기반 예약 엔진, 알림 전송/동의, 소유권/관리 위임 인증, 정책 감사 이력 및 LLM 응대 품질 검증을 순차 추진한다.
