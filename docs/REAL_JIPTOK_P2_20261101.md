# DirectHome Stage 2 — 실거래 집톡이 그룹채팅 (2026-11-01)

## 목적 / 책임 경계
기존 시연용 집톡이는 데모 거래방에서만 사용한다. 실제 매물의 집주인·방문자 채팅에도 별개의 **집톡이 진행 도우미**가 자연스럽게 참가해 방문, 조건 제안, 계약 준비를 챙긴다.

- **집주인 AI 대리인:** 집주인이 사전 등록한 사실에 근거해 답하거나 확인 필요 문의를 집주인에게 이관한다. 현재는 방문자 브라우저의 /owner-agent/invoke 후속 호출에 의존한다.
- **집톡이:** 사실 데이터인 `transaction-state`를 읽고 다음 확인 사항 안내, 아직 양측 확인을 받지 않은 조건의 **제안 카드** 제공, 방문 승인/거절·양측 동의 이벤트를 그룹 대화에 기록. 사람처럼 가장하지 않는다.
- **사람:** 가격/옵션/일정 등 구체 조건을 제시한다. 양측이 같은 version에 **명시적으로 동의**해야 `room_proposals.status='agreed'`이다. 실제 방문은 집주인의 booking 승인만 확정. 집톡이/AI가 자동으로 동의하는 기능 없음.
- **금지:** 가격 조율·절충안 제시·법률적 효력 주장·계약 체결/금전 지급/방문 승인 대행·추측한 사실을 확정으로 기록.

## 구현
1. 서버 `POST /api/rooms/{rid}/messages`가 사람 메시지를 DB에 저장한 후 집톡이 규칙을 실행한다. **브라우저의 추가 호출이 없어도** 관련 집톡이 발화가 남는다. 추가 LLM 호출·토큰 비용 없음. 오류 시 사람 메시지 저장 성공을 취소하지 않는다.
2. `real-jiptok-rules.ts`는 거래 유형별 명확한 숫자·문장 단서만 제안 후보로 추출한다. 질문/부정/불완전 조건은 자동 카드 생성 금지.
   - 월세는 보증금+월세 **단일 묶음**, 전세는 보증금, 매매는 명확한 매매가.
   - 집주인이 **명시적으로** 고양이 등을 허용한다고 발화했을 때에만 `옵션` 제안 카드. 임차인 질문만으로 허용/동의 확정 금지.
   - 후보는 `createProposals`를 거쳐 proposed로 기록. 한쪽만 동의하면 proposed 유지, 양측 동의하면 agreed. 카드의 `source_msg_ids`는 원래 사람 메시지를 가리킨다.
3. 실제 집톡이 발화는 `messages.author_type='assistant'`, `author='집톡이'`로 저장. `room_proposals.card_msg_id`를 채워 **그룹채팅 안에 바로 확인 버튼**을 표시하며, 거래 진행 현황 보드도 함께 갱신.
4. `proposals/create`에서 수동 제안이 들어온 뒤에도 집톡이가 채팅 내에 확인 카드를 남긴다. `proposals/decide`에서 양측 동의 또는 거절이 결정되면 다음 절차를 안내한다. **중간의 1인 동의는 조용히 보류**하고 카드의 당사자별 대기를 표시한다.
5. 실제 방문 예약 승인/거절/취소 후 방문 상태·후속 절차를 집톡이가 안내한다. **승인 대기 단계는 기존 booking_notice가 이미 안내하므로 반복하지 않는다.**
6. `015_real_jiptok_events.sql`: 방+이벤트+키 UNIQUE의 영속 멱등성 원장. 경합 중 같은 질문/이벤트로 집톡이가 여러 번 말하지 못하게 트랜잭션으로 기록한다. 초깃값/방문 승인 정책은 변경하지 않는다.
7. 시연방은 새 규칙/원장에서 제외되고 기존 Ziptalk의 demo 흐름을 그대로 쓴다.

## 발화 정책
- 가벼운 인사: 거래방 당 1회 소개.
- 반려동물/생활 조건 질문: 동일 주제 당 1회 안내; 집주인 명시 허용 시 별도 버전 관리된 제안 카드.
- 금액 질문: 합의처럼 보이지 않도록 보조 질문, 불완전 금액은 추측 금지.
- 구체 조건 제안: 자동 카드 생성 + 그룹채팅 확인 버튼. **제안자가 카드를 눌러 명시적으로 동의해야 한다.**
- 계약/가계약 언급: 먼저 가격·생활 조건 확정 여부를 확인하고 계약일→계약금→잔금/입주로 안내.
- 날짜/방문 승인: 집주인 승인으로 확정된 일정만 완료로 언급.
- 친근한 대화 속 보조 역할이지 거래 상대방처럼 가격을 조정하지 않는다.

## 검증 게이트
- 규칙 단위: 매매/전세/월세, 완결·질문·부정 구분, 반려동물 질문/명시 허용, 이벤트 안내.
- Next+SQLite API: 방 접근 제한, 서버 메시지 발화, 방별 토픽 중복 제거, 조건 source_msg_ids, 실제 인라인 카드, 1인 동의 미확정, 2인 동의 확정, 방문 승인 가이드.
- Playwright PC/Mobile: 그룹채팅에서 카드 확인·양측 체크, 반려동물 질문은 완료가 아님, 모바일 가로 스크롤 없음.
- 전체 기존 시연·예약·집주인 AI 회귀, GitHub verify-fast/e2e, Vercel Preview 및 main Production READY.

## 이후 Stage 3
- 현재 **집주인 AI 대리인은 브라우저 후속 호출**이라 연결 끊김에 취약함. 서버측 내구 작업 큐/재시도와 권한 변경·설정 버전·외부 알림은 다음 단계로 분리.
- 집톡이의 현재 버전은 **규칙 기반 고신뢰 추출**이다. 구어체·복합 문장·한글 숫자 등에서 파싱 한계가 있다. 정황상 모호한 발언은 카드로 올리지 않고 명시 입력을 요청한다. 추후 LLM 요약을 도입하더라도 제안/확정 경계는 변경하지 않는다.
- 실제 Supabase 사용자 2계정 운영 수동 E2E, 부동산 계약의 법률/보안 게이트는 별도 과제다.
