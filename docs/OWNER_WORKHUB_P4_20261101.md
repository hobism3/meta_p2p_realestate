# Stage 4 — 집주인 업무 허브 (2026-11-01)

## 목표
여러 매물을 등록한 임대인이 문의·방문 예약·AI 응대 상태·확인 대기를 한 화면에서 빠르게 파악한다. 집톡이는 절충안을 제시하거나 당사자 동의 없이 계약·가격·방문을 확정하지 않는다.

## 이번 PR 범위 (P4-A)
- 기존 `/api/owner/listings` 데이터 재사용, 추가 DB 쿼리/마이그레이션 없음.
- 등록 매물 수, 문의 거래방 총합, AI 응대 활성 매물 수 요약.
- 매물명/주소 검색, AI 응대 활성/비활성 필터, 문의 거래방 수/이름 정렬.
- 기존 방문 예약 패널, AI 확인 요청 패널, 매물별 관리 링크 보존.
- '문의 거래방 수'는 미처리 업무 개수가 아님을 UI에 명시.

## P4-B 구현 (같은 PR, CI 대기)
- 인증된 owner scope의 기존 예약/문의/AI 실패 서비스 결과를 집계하는 `/api/owner/work-summary` 추가.
- `/owner` 최상단에 현재 확인 업무 총수와 카테고리별 수치, 매물별 업무 카드, 기존 예약/문의 패널 바로가기 추가.
- 예약 조회는 기존의 24시간 만료 처리를 그대로 실행. 응답 개수는 서비스 조회 제한(예약 120/문의 100/AI 실패 40)에 종속되며 전체 누적 건수로 주장하지 않는다.

## 다음 분할 작업 (P4-C)
1. 각 매물의 미확인 owner AI 요청 수/예약 승인 대기 수를 인증된 집주인 범위에서 집계하여 서버 API로 노출. 서로 다른 소유자 데이터 혼합 방지.
2. 업무 카드에 `확인 요청`, `방문 승인 대기`, `AI 응대 실패`를 유형별로 구분하고 우선순위/바로가기 제공. AI 생성 문구와 사용자 승인 상태 혼동 금지.
3. 방문 완료 이후 다음 행동 안내 및 읽기 전용 전환 추적. 미확인 상태를 임의로 '완료' 처리하지 않는다.
4. 등기 PDF 초안 등록의 단계 표시·검증/수정 안내를 개선하되 소유권 확인으로 오인시키지 않는다.

## QA 게이트
- 검색/필터/정렬 조합, 매물 0건 및 1건, 모바일 폭, 로그인 만료.
- 기존 양측 확인 카드·예약·AI 작업 재시도 흐름 회귀 없음.
- CI verify-fast + verify-e2e 및 Preview 테스트 후에만 main 병합.
- 실제 Supabase 서로 다른 2개 계정 수동 E2E, Cron 실실행 관찰, 법률/보안 검증은 여전히 미완료.

## P4-C 적용 (2026-11-01)
- 업무별 방문 승인·직접 답변·AI 실패 중 대표 미처리 거래방을 집주인 범위에서 선택해 바로가기 제공.
- 거래방 링크는 조회 전용 이동이며 승인/답변을 자동 실행하지 않는다. 실제 처리 버튼은 기존 관리 패널에 유지.
- CI 빌드 오류인 Map iterator downlevel spread를 Array.from으로 수정.
- 동일 매물에서 업무 종류별 여러 건이 있을 수 있으므로 대표 거래방 링크는 전체 건수/목록을 대체하지 않는다.
