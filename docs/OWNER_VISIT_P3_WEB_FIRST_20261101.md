# DirectHome P3 — 이용 목적 선택 / 방문 예약·승인 (웹 우선)
작성일: 2026-11-01. 연계: [P1 기획](OWNER_AI_DELEGATE_PRD_20261101.md), [P2 설계](OWNER_AI_DELEGATE_P2_20261101.md)

## 제품 결정
앱 출시 및 외부 알림 발송은 후속 검증 단계로 보류한다. 앱을 만들지 않아도 웹·PWA 푸시는 가능하지만 브라우저 제약, 권한 동의, 유지관리 비용이 있다. 지금은 **앱 없이 직거래 핵심 절차를 끝까지 수행**하는 데 집중한다.

첫 화면에서 **"집주인이신가요?" → `/owner`**, **"집을 구하시나요?" → `/#properties`** 두 갈래를 가장 먼저 제시한다. 로그인 계정은 동일하고, 선택은 접근 권한/소유권을 변경하지 않는다. 기존 매물 탐색 지도·리스트, 거래방, 시연은 유지한다.

## P3 예약 정책
- **방문 예약용 새 테이블** `owner_visit_bookings`, `owner_visit_slot_locks`. 거래방에 붙은 과거 비공식 방문 제안(`visits`)과 분리한다.
- 집주인은 매물별 /owner/listings/[id]에서 가능 요일·시간, '집주인 승인 요청' 모드를 설정한다.
- 방문자는 실제 등록 매물의 거래방에서 날짜·시간을 고른다. Asia/Seoul 기준의 30분 간격 시작점, 1회 **60분** 길이. 현재 이후 60일 범위와 설정된 시간 내에서만 신청한다.
- 신청 시 상태 **requested(승인 대기)**. 같은 매물의 모든 방을 통합해 30분 inventory cell 두 개를 DB 고유 키로 잠근다. 13:00~14:00 신청 후 13:30~14:30 중복 신청은 409. 신청 중에는 다른 사람이 같은 슬롯을 잡지 못한다.
- 집주인이 `/owner`의 방문 예약 관리 또는 거래방에서 **승인/거절**. 승인해야만 confirmed(확정). 요청자/집주인만 취소할 수 있고 거절·취소는 슬롯 잠금 해제. 변경은 현재 예약 취소 후 다시 신청하는 방식.
- 거래방에서 누구나 예약 상태를 볼 수 있다. 요청·확정·거절·취소 시 거래방에 시스템 일정 메시지 1건씩 기록한다. 이것은 **인앱 상태 기록이며 외부 알림 전송이 아니다**.
- 시연용 매물은 이 API 사용 불가. 기존 집톡이·시연 일정 UX 유지.
- 수동(manual) 모드라면 온라인 예약을 생성하지 않고 집주인에게 직접 문의하게 한다.
- 예약 신청자와 소유자만 자신의 방에 접근하고, 집주인의 전체 예약 목록은 소유권 기준으로 조회한다.
- 이전 `visits` API는 과거 비공식 제안용으로 유지하되 실제 매물 방문자가 직접 '수락됨'을 만드는 우회 경로는 차단한다.

## API
- `GET /api/rooms/{rid}/bookings?date=YYYY-MM-DD`: 방 접근 제어, 공개 가능한 시간대/해당 방 예약 상태.
- `POST /api/rooms/{rid}/bookings`: 방문자 슬롯 신청, 서명된 사용자 ID, 실제 매물/가능 시간/충돌 검증.
- `PATCH /api/rooms/{rid}/bookings/{bid}`: 집주인 confirm/decline, 소유자 또는 원 요청자 cancel; 조건부 UPDATE로 중복 결정 방지.
- `GET /api/owner/bookings`: 집주인 자신이 등록한 매물의 신청·확정 일정 조회.
